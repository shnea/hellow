# 운영·관측·복구

필요시 확인: 운영 환경·로그·알림·백업·복구·유지 비용을 다룰 때.

적용 범위: 조건부. 지속 운영·배포·사용자 데이터 관리가 필요할 때 적용한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 환경과 담당 | 개발·검증·운영 분리 필요성, 운영 주체·접근 범위 | 확정: 개발 PC 192.168.0.55 / 운영 NAS 192.168.0.93. 상세 사양·도메인·포트는 환경 기준. 운영 담당·온콜 정책은 미정. |
| 상태와 장애 감지 | 로그·상태 확인·지표·알림의 필요 수준 | 확정: MVP부터 구조화 로그·Trace ID·Health·기본 Metrics·배포 버전. OpenTelemetry → Prometheus/Loki/Tempo → Grafana 기본 방향. Audit/보안 접속/앱 로그 목적 분리. |
| 데이터 보호와 복구 | 백업 대상·주기·보관·복원 확인·허용 가능한 손실 | 확정: DB·파일·설정의 백업 범위와 Restore 검증, 삭제·익명화 시 파생 데이터 추적, 재생성 가능한 파생 데이터 구분. RPO/RTO·주기·보존기간 미정. |
| 유지 비용 | 자원·비용 확인, 업데이트·정리·지원 종료 기준 | 확정: Organization별 사용량·AI 비용·메시지 비용 분리. 유료 사용 전 한도 적용. 용량·Quota·알림 임계치·담당자·보존 수치 미정. |
