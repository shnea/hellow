# Git·릴리스·배포

필요시 확인: 커밋·푸시·릴리스·배포를 요청받았거나 관련 구성을 변경할 때.

적용 범위: Git·릴리스·배포를 사용하는 범위에 맞게 적용한다. 설치형 앱·패키지는 배포 대상을 그에 맞게 바꾼다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 브랜치와 검토 | main 중심·작업 브랜치·PR, 변경 검토 기준 | 현재: 빈 원격 저장소에 로컬 main 초기화. 팀 브랜치/PR 보호 정책 및 CI/CD trigger는 미정. |
| 커밋·푸시 | 시점·포함 범위·위임 범위, 기존 변경의 처리 | 사용자 위임: 큰 작업 단위 완료 및 관련 검증 통과마다 완료 상태·남은 일을 기록하고 커밋·push한다. 첫 커밋은 요구사항·골든패스·환경·스킬 구성. |
| 버전과 산출물 | 버전 식별, 재현 가능한 빌드, 게시·보관 대상 | 확정: registry.shnea.kr/hellow-이미지명:커밋SHA. 로그·Trace에 실행 버전 연결. 운영에는 이미지 실행에 필요한 최소 배포 파일만 보관. |
| 배포 대상과 시작 조건 | 서버·스토어·레지스트리, 수동·push 자동·별도 승인 | 확정: /volume2/homes/hellow/의 운영 NAS, 개발·운영 Compose. 주소·포트·암호화는 환경 기준. 배포 자동화·시작 조건은 미정이며 커밋 위임만으로 배포 완료를 주장하지 않는다. |
| 배포 검증·실패 대응 | 선행 검사·환경 변경·데이터 이관·성공 확인·복구 방법 | 확정: Health/Readiness, 이전 앱·DB/API/Event 호환, 롤백·Draining 검토. HTTP 무중단과 WS/WebRTC 세션 보존 별도 검증. 공유 NAS/DB의 공통 장애 지점은 남는다. |

## 선택 배포 요구

확정: 독립 배포 가능한 특정 서비스만 선택하거나 전체 서비스를 배포할 수 있어야 한다. 배포 대상을 이미지 버전(커밋 SHA)과 분리한다. 선택하지 않은 서비스를 불필요하게 재시작하지 않는다.

`user배포`, `all`은 동작 예시이며 태그 문법이나 신규 user 서비스 생성 지시가 아니다. 태그·커밋 메시지·수동 입력 등 호출 방식과 CI/CD trigger는 미정이다. 상세 요구는 [환경 기준](../../../../../docs/infrastructure.md#cicd-배포-대상-선택)을 따른다.

공통 모듈·DB/API/Event 변경은 선택 배포의 호환성과 동시 반영 필요성을 확인한다. 대상 허용 목록·잘못된 입력 거부·빌드 영향·마이그레이션·상태 확인·롤백, 실시간 세션 Draining은 구현 전 상세설계한다.
