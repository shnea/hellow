# 구조·코드·협업 규칙

필요시 확인: 폴더·모듈 경계·코드 규칙·협업 방식을 변경할 때.

적용 범위: 공통 정의 항목. 프로젝트 규모에 필요한 정도만 정한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 저장소·폴더 구조 | 단일·분리·모노레포 여부, 소스·테스트·문서·임시 결과 위치 | 확정: 단일 hellow 저장소. 구체적인 앱·모듈 경로는 첫 구현 때 결정하며 문서 단계에서 빈 계층을 만들지 않는다. |
| 책임과 경계 | 모듈·계층·외부 연동의 경계, 공유 코드의 위치 | 확정: Core는 업무 트랜잭션, Contact Center는 Agent 상태·Queue·Routing·세션, Worker는 장시간 작업, Integration은 Provider Adapter. AI Layer는 기존 Domain API를 사용하는 보조 계층. |
| 코드 규칙 | 이름·포맷·타입·오류 처리, 기존 스타일과 자동화 도구 | 확정: 사람이 흐름과 수정 위치를 추적하기 쉽게 책임별로 응집. 의미 없는 전달 계층·과도한 파일 분리·Helper/Common/Manager 같은 모호한 이름을 피한다. 상세는 개발 원칙. |
| 작업 판단 범위 | AI가 정할 수 있는 선택, 사용자와 논의할 결정 | 확정: 사용자 확정 기술·범위·보안을 유지하고 미정 사항은 필요한 시점에 근거로 결정한다. Entity마다 서비스나 DB를 나누지 않는다. |
| 협업 조건 | 다른 사람·에이전트의 변경 보존, 병렬 작업이 필요한 경우의 범위 | 확정: 기존 변경 보존. 큰 작업 단위 검증·인계·커밋·push. 병렬 에이전트는 명시 요청 또는 해당 스킬의 필요한 절차에 한한다. |
