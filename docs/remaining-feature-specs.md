# Hellow 남은 기능 상세 개발 명세

2026-10-04 기준. 먼저 [AI 인계서](ai-development-handoff.md)를 읽는다. 이 문서는 남은 작업의 실행 명세이며 신규 기능을 구현했다는 보고가 아니다.

**아래 신규 테이블·API·권한 이름은 모두 설계 제안이다.** 기존 코드와 충돌 여부를 확인해 가장 작은 일관된 구현을 선택한다. 사용자가 확정한 업무 요구와 기존 권한·데이터 경계는 필수다. 미정인 비용·보존기간·발신 공급자·운영 정책은 임의 확정하지 않는다.

## 공통 개발 계약

### 권한과 조회

- 직원 요청은 검증된 OIDC Identity의 `issuer + subject`, 활성 Membership, 현재 조직, 기능별 권한으로 처리한다. subject만으로 동일인을 판정하지 않는다.
- `WorkspaceAccess`, `MembershipAccess`, `BusinessScope`의 기존 범위 계산을 사용한다. 기능 A의 넓은 Scope를 기능 B에 재사용하지 않는다.
- 목록·합계·검색·자동완성·파일 URL·WS 이벤트에도 범위를 먼저 적용한다. 전체 행을 가져온 뒤 프런트에서 숨기는 구현은 금지한다.
- `ORGANIZATION`은 현재 조직 전체이지 플랫폼 전체가 아니다. 최고관리자의 조직 설정 관리 권한을 상담 내용 접근 권한으로 바꾸지 않는다.
- SELF의 이관 참여자 읽기 관계를 보존하되 참여 사실만으로 쓰기·재생 권한을 부여하지 않는다. `recording:read` 등 해당 기능 권한도 필요하다.
- 고객 공개 세션은 해당 요청의 제한된 capability다. 직원 JWT나 고객 전체 CRM 이력 열람 권한으로 취급하지 않는다.
- 새 권한을 추가할 때 서버 허용 목록, 프런트 라벨/메뉴, 역할 편집, 최초 관리자 생성, 기존 조직 migration, 검사 fixture를 함께 갱신한다. 기존 일반 직원에게 새 권한을 일괄 부여하지 않는다. 부여 정책이 미정이면 비활성 기본값을 사용한다.

### 저장과 API

- 생성·발송·외부 Action은 request ID와 본문 fingerprint로 중복을 막는다. 같은 ID·같은 내용은 기존 결과, 같은 ID·다른 내용은 충돌이다. 유일 범위를 조직·행위자·작업 종류에 맞게 정의한다.
- 수정은 expectedVersion을 받고 409에서 입력과 기준 버전을 보존한다. 최신 값을 무조건 덮어쓰거나 자동 재실행하지 않는다.
- 트랜잭션 내 업무 저장과 후속 이벤트의 일관성을 보장한다. 외부 호출은 DB 잠금 밖에서 수행하고 Outbox/지속 Job을 필요한 기능부터 도입한다.
- 이벤트에는 조직·원본 ID·event ID·원본 버전·발생 시각을 넣는다. at-least-once 전달을 전제로 소비 중복 제거와 역순 이벤트 무시를 구현한다. 외부 공급자까지 정확히 한 번 실행된다고 약속하지 않는다.
- 시간은 명확한 Instant와 조직/입력 시간대를 사용한다. 기존 LocalDateTime 열은 저장 의미를 먼저 확인하며 시간대 없는 값을 임의로 UTC로 재해석하지 않는다. 기간 조회는 `[from, until)`을 권장한다.
- 목록은 기존 페이지 계약과 정렬·최대 크기를 맞춘다. 대량 조회/다운로드에서 무제한 메모리 적재를 금지한다.
- API 오류의 인증 실패·권한 거부·없는 객체·검증 오류·버전 충돌·일시 장애를 구분한다. 403을 로그인 만료로 처리하지 않는다.

### UI와 데이터 보존

- 기존 목록·공통 상세·내부 팝업·초안 보존 패턴을 재사용한다. 새 기능 때문에 작성 중 상담·통화를 교체하지 않는다.
- 빈 상태, 로딩, 오류/재시도, 읽기 전용, 권한 없음, 저장 중, 충돌, 완료 상태를 갖춘다. 표시할 데이터가 없을 때 가짜 통계를 넣지 않는다.
- 저장된 직원 닉네임/아이디를 표시하고 UUID 노출을 피한다. 이름을 못 찾으면 의미 있는 미확인 표시를 사용한다.
- 모든 migration은 기존 데이터·소유권·팀·원문·감사를 보존한다. 완료된 migration을 편집하지 않는다.
- 새 기능의 성공·실패·취소·재시작 상태를 영속화한다. 브라우저 타이머와 메모리 변수만으로 업무를 끝내지 않는다.

## F01 상담 현황과 기본 통계

**상태:** 2026-10-04 F01 코드 구현·격리 검증 및 개발 서버 `aea94bf`/DB V21 반영 완료. 직원 상태·미처리 현황, 기간/팀/담당자/채널/분류/결과 필터, 접수·통화·문서·콜백 집계와 추이/분포 차트를 추가했다. 기존 ACD 상태·권한·원천을 재사용한다. 현재 계약은 [상담 현황·기본 통계](consultation-reporting.md), 최종 검사·커밋·배포 여부는 [작업 인계](handoff.md)가 기준이다. 기존 계정 권한 부여·실제 기기 수락과 운영 NAS 배포는 남아 있으며 아래 항목은 완료 조건과 설계 근거로 유지한다. 근거: 요구사항 25~27, 43, 60장.

### 사용자 흐름

1. 권한자가 현황/통계 메뉴를 연다.
2. 현황에서는 범위 안 상담사의 대기·수신 제안·통화·후처리·후속 업무·자리비움·오프라인을 본다.
3. 통계에서는 기간·팀·담당자·채널·분류·결과를 선택하고 실제 집계값을 확인한다.
4. 상세 접근 권한이 있을 때만 목록/상담 상세로 이동한다. 집계 권한만 있으면 고객명·연락처·본문은 노출하지 않는다.

### 데이터와 계산

- `AgentPresence`, `AssignmentAttempt`, `QueueItem`, `Consultation`, `FollowUpAction`, `WorkTransfer`를 원천으로 삼는다. 화면에 맞춰 동일 상담을 별도 테이블로 복제하지 않는다.
- 현재 상태는 RoutingService의 의미와 일치해야 한다. 통계 구현용으로 가용 상태와 업무 상태의 별도 규칙을 만들지 않는다. 오래된 heartbeat는 오프라인/만료로 표시하고 실제 시각을 제공한다.
- 초기 통계는 범위 필터 SQL 집계로 시작한다. 이후 부하 근거가 있을 때 재생성 가능한 집계 테이블을 도입한다.
- 필수 지표 후보와 집계 정의를 구현 전 문서화한다:

| 지표 | 권장 정의와 주의점 |
| --- | --- |
| 접수 건수 | 기간 내 신규 접수 수. 상담 문서 버전·배정 재시도와 별개 |
| 수락 건수 | 한 번이라도 상담사가 수락한 접수. 실제 음성 연결 성공과 구분 |
| 음성 연결 건수 | 양측 연결이 확인되어 callStartedAt이 있는 통화 |
| 미수락 자동 콜백 | callbackFollowUpId로 전환된 원본 수. 실패 통화와 임의 합산 금지 |
| 대기 시간 | 접수→최초 수락. 미수락 건은 별도 현재 대기/종료 대기로 계산 |
| 통화 시간 | callStartedAt→callEndedAt. 진행 중은 서버 now 기준이며 null을 0초 성공으로 처리하지 않음 |
| 완료 상담 | 업무 완료 건. 통화 종료 수와 구분 |
| 콜백 처리 | 미배정/배정/처리 중/완료/실패/취소. 실패 후 재예약과 새 콜백을 구분 |
| 수신 시도 결과 | AssignmentAttempt 기준 제안·수락·거절·미수신·시간 초과. 접수 수와 섞지 않음 |

- 최초 수락/후처리 시작 등 필요한 시각이 원천에 없으면 신규 수집을 추가하고 기존 데이터는 ‘측정 불가’로 둔다. 과거 값을 추정해 채우지 않는다.
- 이관 통화는 조직 합계에서 원본 통화를 한 번만 센다. 상담사별 시간 배분은 실제 참여 구간 증거가 있을 때만 제공하고, 없으면 담당 변경 횟수 등 증명 가능한 지표를 사용한다.
- 기간 집계가 접수 기준인지 종료 기준인지 UI와 API 계약에 명시한다. 다른 기준의 분모/분자를 조합한 비율을 만들지 않는다.

### API 및 권한 제안

- `GET /api/monitoring/agents`, `/api/monitoring/summary`.
- `GET /api/reports/consultations`, `/api/reports/followups`.
- 새 권한 후보 `agent:monitor`, `report:read`; 각 SELF/TEAM/ORGANIZATION 정의를 별도로 확정한다. 직원 상태는 Membership 팀 범위로, 업무 집계는 각 원본의 허용 범위로 제한한다.
- 보고서 권한이 상담 원문 조회를 암묵 부여하지 않도록 한다. 조합 정책은 ‘보고서 범위 안의 수치만’과 ‘원문 이동 시 consultation:read 재검사’로 분리한다.
- 응답에 기준 시각·기간·시간대·집계 정의 버전과 데이터 미수집 여부를 포함하는 방식을 권장한다.

### 화면 및 구현 순서

1. 권한/집계 사전과 SQL 검사 → 기본 지표 API → 좁은 범위 직원 상태 API.
2. 기존 통계 메뉴를 실제 페이지에 연결한다. 상단 소형 필터, 핵심 수치, 넓은 표, 필요한 추세 차트 순서다. 모든 내용을 큰 카드로 채우지 않는다.
3. 자동 갱신 실패를 실제 0건/오프라인으로 바꾸지 않는다. 마지막 갱신 시각과 재시도를 표시한다.
4. 기존 폴링을 고려해 중복 타이머를 피한다. 실시간 구독을 도입하면 재인증/권한 회수/재접속 snapshot을 제공한다.

### 완료 조건

- 두 조직·다른 issuer·SELF/TEAM/ORG에서 숫자와 행의 격리가 성립한다.
- 0건, 진행 중, 취소, 미연결, 재배정, 이관, 미등록, 자동 콜백, 날짜 경계의 수동 계산 fixture와 결과가 일치한다.
- ‘상담사 상태 조회만 가능’한 사용자가 고객명/본문/녹음에 접근할 수 없다.
- 실제 메뉴·필터·빈 상태·오류·상세 연결과 PC/태블릿/모바일 검수를 완료한다.

## F02 고객 실시간 채팅

**상태:** 양방향 대화·저장·복원·종료 구현 및 격리 검증 완료. 최종 모델/API·정책은 [고객 채팅 계약](customer-chat.md), 서비스 반영·실제 기기 수락은 최신 [인계](handoff.md)가 정본이다. 아래 데이터/API 제안은 초기 설계 후보이며 Queue를 대화 aggregate로 재사용한 최종 계약과 구분한다. 과거 단건 문의는 소급 변환하지 않는다.

### 최소 사용자 흐름

- 고객이 기존 공개 진입점에서 채팅을 선택하고 연락처/문의로 접수한다.
- ACD를 통해 한 상담사가 수락한다. 고객과 상담사는 같은 대화의 메시지를 주고받는다.
- 고객 새로고침/망 전환 시 현재 세션과 누락 메시지를 복원한다. 상담사가 대화를 끝내도 기록은 남고 후처리/상담 저장은 별도다.
- 고객 채팅에 음성 마이크 권한을 요구하지 않는다. 기존 음성 경로와 30초 자동 콜백 동작을 변경하지 않는다.

### 데이터 제안

- `ChatConversation`: organizationId, queueCode 또는 interaction 참조, 채널, 상태, version, 시작/종료 시각. 원본 접수와 하나의 업무로 연결한다.
- `ChatMessage`: conversationId, server sequence, sender 종류/Identity, clientMessageId, body, createdAt, 선택 attachmentId. `(conversation, sender, clientMessageId)` 유일성.
- sequence는 대화별 정렬과 재접속 cursor의 기준이다. 서버 저장 완료 전 ‘전송 완료’로 표시하지 않는다.
- 고객 최초 문의를 대화 시작 메시지로 연결하되 재시도로 중복 삽입하지 않는다. 과거 단건 문의를 가짜 양방향 대화로 변환하지 않는다.
- 최소판은 텍스트부터 구현한다. 첨부·읽음·입력 중·메시지 수정/삭제는 각각 별도 범위를 명시하고 사용자 기대와 맞춘다. 원문을 흔적 없이 덮어쓰지 않는다.

### API 및 실시간 설계 제안

- 직원용 `GET/POST /api/chat/conversations/{id}/messages`, cursor 기반 복원, 종료 명령.
- 고객용은 기존 Support capability 검증을 재사용한 해당 세션의 전용 경로. 직원 경로를 공개하지 않는다.
- HTTP 명령 + SSE 수신 또는 WS 양방향 중 하나를 선택하고 선택 이유를 기록한다. 같은 메시지 저장 로직을 전송 방식별로 복제하지 않는다.
- 인증 토큰/capability를 접근 로그에 남는 URL query에 싣지 않는다. 브라우저 전송 제약에 맞춰 기존 인증 구조와 안전한 인증 방식을 정한다.
- 이벤트는 commit 이후 발행하고 재접속 시 DB에서 `afterSequence` 이후를 읽는다. Redis pub/sub만을 유일 원본으로 삼지 않는다.
- 읽기 권한은 현재 상담 범위와 대화 참여 관계, 쓰기는 현재 처리 권한·담당·상태를 확인한다. 조직 변경/권한 회수 시 구독을 종료한다.

### 배정 및 UI

- 초기 제안: 기존 한 Identity 한 업무 정책을 유지한다. 동시 여러 채팅 허용은 별도 용량/배정 정책 확정 후 진행한다.
- 워크스페이스 안에서 대화와 상담 기록을 오갈 수 있게 하고 입력 초안과 고객 문맥을 유지한다. 채팅 전체를 기존 상담 문서에 계속 덮어쓰지 않는다.
- 전송 중/실패/재시도/연결 끊김/종료를 표시한다. 사용자가 과거 메시지를 읽는 동안 자동 스크롤로 바닥에 끌어내리지 않는다.
- 채팅 미수락 때 콜백 전환 여부, 종료 후 재개 시간, 첨부 허용은 미정이다. 음성의 30초 정책을 무단 적용하지 말고 구현 전 필요한 결정만 받는다.

### 완료 조건

- 양방향 실제 전송, 순서 보장, 동일 메시지 재시도, 새로고침/오프라인 복원, 종료 경합, 다른 조직·세션의 메시지 차단.
- 상담사 이관 뒤 이전/현재 담당의 읽기·쓰기 경계 확인. 고객은 내부 메모와 상담 기록을 볼 수 없음.
- 공급자/실시간 장애에서도 상담 문서 저장과 다른 고객 통화가 정상 동작.

## F03 지식관리

**상태:** 확정 후속. AI 없이 목록·검색·원문을 먼저 완성한다. 근거: 사용자 승인 추가 기능, 요구사항 35장.

- 화면: 전체 너비 목록, 검색/분류/상태 필터, 읽기 상세, 권한 있는 편집·버전 이력. 문서 출처 링크를 고정 ID로 제공한다.
- 데이터 제안: `KnowledgeDocument`와 revision, 제목/분류/본문 Editor JSON 또는 검증된 문서 형식, 조직/소유자/팀, 공개 범위, 게시 상태, version, 첨부 관계.
- 초안과 게시 문서를 구분한다. 보관·삭제·권한 변경 후 검색/AI 인덱스에서도 사라져야 한다. 원문·revision을 남기는 범위는 보존 정책에 맞춘다.
- 권한 후보: `knowledge:read/write/publish`. 읽기와 게시 권한은 별도. 공개 범위가 있어도 현재 Membership과 기능 권한을 우회하지 않는다.
- API 제안: `/api/knowledge`, `/{id}`, `/{id}/revisions`, 게시/보관 명령, scoped 검색.
- 검색은 우선 DB 기반부터 구현 가능하다. 외부 인덱스를 선택해도 권한 필터와 원문 재검사를 제공한다. 제목·snippet·검색 건수도 범위 제한 대상이다.
- 첨부는 플랫폼 PRIVATE 업로드와 문서 관계 검사. 상담 첨부의 queue 의존을 억지로 재사용하지 말고 파일 저장 Provider와 업무 소유 관계를 분리한다.
- 완료: 다른 조직/비공개 초안 검색 차단, 수정 충돌, 첨부 권한, 게시/회수 반영, 원문 링크 유지, AI 없이 직접 검색·열람 가능.

## F04 녹음 STT와 상담 요약

**상태:** 녹음은 이미 구현. 텍스트 변환과 AI 요약이 신규다. 근거: 요구사항 31~34, 40, 80장.

### 처리 흐름

1. 녹음 파일 저장 확정을 확인한다. fileId가 없거나 저장 실패면 STT를 시작하지 않는다.
2. 중복 없는 STT Job을 생성한다. 공급자 작업 ID·상태·재시도·lease를 영속화한다.
3. 결과 segment와 시간 구간을 저장한다. 화자 구분을 공급자/음원으로 입증할 수 없으면 상담사/고객으로 단정하지 않는다.
4. 텍스트 변환 완료 후 별도 요약 Job을 생성한다. 원본 revision·모델·프롬프트 버전·생성 시각을 연결한다.
5. 상담사는 요약 초안을 확인하고 필요한 부분만 현재 상담 기록에 반영한다. 자동 상담 완료와 자동 덮어쓰기는 금지한다.

### 데이터 및 API 제안

- `TranscriptJob/Transcript/TranscriptSegment`, `SummaryJob/SummaryDraft`; organizationId, recordingId, sourceVersion, provider/model, 상태·오류 코드, 사용량 포함.
- 상태 후보 PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED. 재시도 가능 오류와 최종 실패를 구분한다.
- 원본 recordingId + 목적 + 설정 버전으로 중복 보장. 사용자의 명시적 재생성은 새 revision으로 처리한다.
- API: 녹음별 transcript/summary 조회, 명시적 생성/재시도/취소, 요약 적용 명령. 새 권한 후보 `transcript:read/manage`, `summary:read/generate`는 기존 녹음·상담 범위와의 결합을 정한다.
- 녹음을 못 듣는 직원에게 transcript로 우회 노출하지 않는다. 파일 URL 만료는 fileId로 재발급하며 공개 영구 URL을 저장하지 않는다.

### 비용 및 장애

- 공급자·외부 전송 허용 범위·요금 부담자·조직 한도를 먼저 확정한다. 실제 유료 호출 전에 서버 한도를 적용한다.
- 전역 배정/상담 저장 트랜잭션에서 외부 모델을 호출하지 않는다. timeout·backoff·최대 시도·수동 재시도를 지속 Job으로 관리한다.
- DB commit 전후 재시작, 공급자 성공 응답 유실, 중복 callback, 취소 뒤 늦은 결과를 처리한다. 공급자 idempotency 지원 범위는 실제 계약을 확인한다.
- 원본 삭제/권한 회수 시 신규 처리와 결과 열람을 차단하고 삭제 정책에 따라 파생 결과를 정리한다.
- 완료: 녹음 실패와 통화 실패를 구분, Job 재시작·중복 방지, 타 조직/타인 권한 차단, 상담사 확인 전 원문 보존, 공급자 장애 중 상담 정상.

## F05 AI 정책과 도우미

**상태:** 후속 개발. 단일 거대 ‘AI 기능’으로 구현하지 않고 아래 네 단위로 나눈다.

### F05A 정책과 사용량

- 공급자 Adapter와 `AiProfile`을 분리한다. 비밀키는 서버 비밀 관리에 두고 브라우저/감사 본문에 노출하지 않는다.
- 조직에서 허용 모델·기능·외부 데이터 전송·예산/요청 한도를 설정한다. 팀은 상위 허용 범위 안에서만 제한/선택한다.
- 실행 전 budget 예약, 실행 후 실제 사용 정산, 취소/실패 환원, 동시 요청 한도를 서버에서 처리한다. 사후 사용량 표만으로 비용 제한을 완료 처리하지 않는다.
- 사용 이력에 모델·기능·원본 식별·비용·상태·수행자를 기록하되 전체 상담 본문을 일반 로그에 저장하지 않는다.

### F05B 읽기 전용 도우미와 RAG

- 기존 상담 작업을 유지하는 패널. 초기판은 허용된 상담 요약·지식 검색·출처 제시부터 구현한다.
- 검색 전에 조직/범위/현재 권한을 적용하고 반환 원문을 다시 확인한다. 다른 조직 문서를 넓게 검색한 후 답변에서 지우는 방식은 금지한다.
- 검색 chunk에는 원본·revision·조직·범위를 연결한다. 원문 변경/삭제/권한 회수의 인덱스 갱신과 실패 재시도를 추적한다.
- 답변 출처의 문서/상담 링크를 제공하고 확인 불가능한 근거를 만들어내지 않는다. 오래된 버전 여부를 표시한다.
- 검색 문서와 상담 본문은 데이터다. 문서 속 명령으로 Tool·시스템 지침·권한을 바꾸지 못하게 한다.

### F05C 업무 Action

- 허용된 Tool 등록부·입력 schema·권한·dry-run 결과·실행을 구분한다. 임의 SQL·코드 실행·DB 직접 수정 기능을 주지 않는다.
- 읽기/화면 필터 조작과 저장/이관/발송을 구분한다. 기존 Domain API와 validation, expectedVersion, request ID를 재사용한다.
- 사용자 확인이 필요한 변경은 대상·전후 값·영향·외부 발송 여부를 구체적으로 보여준다. 확인한 payload와 실제 실행 payload가 같아야 하며 확인 후 권한/버전을 다시 검사한다.
- 같은 확인/응답 재전송으로 콜백·문자·이관을 여러 번 만들지 않는다. AI 답변의 ‘완료’는 실제 서버 결과 이후에만 표시한다.

### F05D 검증

- SELF/TEAM/ORG, 타 조직, 권한 회수, 악의적 문서 지시, 삭제된 출처, 예산 동시 소진, provider timeout/429를 검증한다.
- AI를 꺼도 고객 조회·상담 저장·콜백·통화는 정상 동작한다.
- 공급자/모델·가격·데이터 보존 계약은 구현 시 최신 공식 계약을 확인한다. 이 문서는 특정 공급자 선택을 확정하지 않는다.

## F06 조직 내부 채팅

**상태:** 확정 후속. 고객 채팅과 별도 사용자·권한 모델이다.

- 방 유형(1:1/그룹/팀), 초대/퇴장 권한, 과거 대화 열람 범위, 보존·첨부·알림은 구현 전 최소 범위를 정한다. 권장 첫 단위는 동일 조직의 1:1 및 명시적 참여자 그룹이다.
- 직원은 현재 활성 Membership으로 참여한다. 조직 A의 방에 같은 Identity의 조직 B 권한을 사용할 수 없다.
- 데이터 제안: `InternalRoom`, `RoomMember`, `InternalMessage`, 읽음 cursor. F02의 전달/중복 제거 기반은 공유할 수 있으나 공개 고객 capability는 수용하지 않는다.
- 메시지 전송은 방 참여 및 현재 조직 권한을 재확인한다. 탈퇴/직원 삭제/권한 회수 시 새 메시지와 실시간 구독을 차단한다.
- unread 수·알림 미리보기·검색·첨부도 방 범위로 제한한다. 상담 원문 공유 링크를 보냈다고 수신자에게 상담 열람권을 부여하지 않는다.
- 현재 상담을 끊지 않는 패널/메뉴, 전송 실패·재접속·읽음 보존을 제공한다.
- 완료: 비참여자/다른 조직 차단, 중복 전송·누락 복구·동시 읽음·회수 후 연결 차단. F02와 내부 대화가 섞이지 않음.

## F07 사용자 정의 필드

**상태:** 후속 신규. 기존 분류·템플릿·브랜딩 오버라이드와 별개로 고객/상담 추가 필드를 만든다. 근거: 요구사항 21, 42장.

- 대상 범위는 고객/상담부터 선택한다. text/number/date/boolean/single-choice 등의 최소 타입, 필수 여부, 표시 순서, 선택지 안정 ID를 정의한다.
- 제안 모델: `CustomFieldDefinition`과 version, 대상·조직·key·label·type·validation·active, 고객/상담 값. JSONB 또는 별도 값 테이블은 검색/집계 요구를 보고 선택한다.
- 필드명은 식별자가 아니다. 이름 변경 후 과거 값이 유실되지 않게 stable key를 사용한다.
- 사용 중 타입 변경·선택지 삭제·필수 전환은 기존 데이터에 미치는 영향을 보여주고 migration 또는 새 버전으로 처리한다. 과거 상담 값/표시 의미를 바꾸지 않는다.
- 값 저장은 원본 고객/상담 쓰기 권한과 version을 검사한다. 별도 공개/민감 필드 정책이 필요하면 UI뿐 아니라 API 응답을 제한한다.
- 기존 내장 고객명·번호·상담 분류를 중복 필드로 만들지 않는다. 코드/SQL 실행식은 지원하지 않는다.
- 완료: 조직별 정의 격리, 서버 타입 검증, 초안/충돌/과거 표시, 필드 비활성 뒤 값 보존, 필터/내보내기 권한.

## F08 외부 메시지 발송

**상태:** 메시지 발송 버튼은 후속 안내만 존재. SMS/이메일/카카오는 공급자별 Adapter로 단계적으로 구현한다. 근거: 요구사항 18, 41, 61, 70, 74장.

- 사전 결정: 첫 채널, 공급자, 발신자 인증/계정, 운영 메시지와 마케팅 범위, 수신 허용 정책, 비용 부담·한도. 실제 발송과 유료 호출에는 별도 승인 범위를 확인한다.
- 흐름: 고객/상담/콜백에서 수신자·템플릿·본문 미리보기 → 명시적 발송 → 대기/처리/성공/실패 표시 → 이력.
- 데이터 제안: `OutboundMessage`, 발송 attempt, providerMessageId, callback event, requestKey, 조직/수행자/원본 관계, 발송 당시 수신자와 템플릿 snapshot.
- Provider 접수 성공과 단말 전달 성공을 구분한다. 상태를 모르는 timeout에서 무작정 새 ID로 재발송하지 않는다.
- API 제안: 발송/조회/취소 가능한 상태의 취소/결과 이력. `message:send/read`와 원본 데이터 범위, 발송 예산을 함께 검사한다.
- Webhook은 공급자 서명/기한/재전송/역순 상태를 검증한다. body의 organizationId를 신뢰하지 말고 등록한 공급자 계정과 작업 ID에서 조직을 찾는다.
- 수신자/본문은 일반 로그에서 마스킹한다. 전역 배정 잠금 밖 worker로 발송한다.
- 완료: mock 공급자와 sandbox에서 중복 발송·응답 유실·비용 제한·서명 실패·권한 회수 검증. 사용자 동의 없는 실제 고객 발송 테스트 금지.

## F09 전문 분야 기반 배정

**상태:** LONGEST_IDLE 단일 순차 배정은 이미 존재. Skill Based Routing은 후속 확장이다.

- 팀/직원별 기술·언어·업무 분야와 요청별 요구 조건을 정의한다. 기본 배정과 fallback을 명시한다.
- 적합성 필터 뒤 기존 LONGEST_IDLE를 적용하는 단순 확장부터 권장한다. 기술 없음/후보 없음/모든 후보 거절 시 정책은 사용자와 정한다.
- 기존 전역→조직→접수 잠금, 하나의 Identity 한 활성 업무, 부분 unique index, heartbeat·권한 검사를 유지한다.
- 배정 사유/규칙 버전을 attempt에 남겨 왜 해당 상담사인지 설명 가능하게 한다.
- 신규 CALL의 요청 전체 30초 마감이 우선한다. 기술 검색/재시도로 마감을 무한 연장하지 않는다.
- 완료: 동시 후보 경쟁, 다른 조직의 동일 Identity, 규칙 변경 중 제안, 권한 회수, fallback, 중복 제안 없음.

## F10 보이는 ARS와 상담 시나리오

**상태:** 후속. 웹 분기와 전화망 IVR은 구현 채널이 다르다.

- 첫 단위는 공개 웹에서 선택 → 안내/분류 → 상담 요청으로 연결되는 게시된 시나리오를 권장한다. 전화망 음성 안내는 F14와 별도다.
- 데이터 제안: 시나리오 stable ID, 초안/게시 version, node/edge, 선택지, 종료/안내/접수 동작. 기존 고객 접수를 재사용한다.
- 게시 전 도달 불가 노드, 끊긴 연결, 무한 반복/최대 단계, 잘못된 분류·대상을 검증한다. 실행 중 세션은 시작한 게시 버전에 고정한다.
- 노드에 임의 코드·SQL·외부 URL 실행을 허용하지 않는다. 민감값을 URL에 넣지 않는다.
- 운영시간/휴무/대체 안내가 필요하면 조직 시간대와 정책을 먼저 확정한다. 지금 브랜딩 설정만 존재하므로 운영시간이 구현돼 있다고 가정하지 않는다.
- 완료: 초안 비공개, 권한별 편집/게시, 구버전 진행 복원, 반복 클릭 접수 한 건, 취소/마감/없는 분류 처리.

## F11 고급 통계와 내보내기 연계

**상태:** F01 뒤 확장. 채널·팀·분류·시간대별 추세와 SLA, 예약/콜백 성과 등을 실제 운영 지표 합의 후 추가한다.

- 평균/중앙값/백분위, SLA 분모, 영업시간 포함 여부, 이관 시간 귀속, 미수집 기간을 정의한다. 측정되지 않은 수치를 만들지 않는다.
- 대량 집계가 필요하면 원천 event ID/버전 기반으로 중복 제거하고 재생성 가능한 projection을 만든다. 원천과 projection 차이 검증·재처리 기능을 갖춘다.
- 캐시는 조직·실효 범위·필터·권한 revision을 구분한다. 권한 변경 전 넓은 집계를 재사용하지 않는다.
- 다운로드는 D04를 재사용하며 고객 식별정보 포함 여부와 권한을 별도 처리한다.
- 완료: 원천 대조, 지연/중복/역순/재생성, 시간대 경계, 데이터 삭제 반영, 집계 캐시의 범위 누출 없음.

## F12 공지와 커뮤니티 및 뉴스레터

**상태:** 후속 단계. 세 기능을 하나의 개발 단위로 묶지 않는다.

- 공지: 조직/팀 대상 게시·예약/종료가 필요하면 정책 확정, 첨부·조회 범위·게시 이력. 읽음 확인은 필요 여부를 정한다.
- 커뮤니티: 게시글/댓글/편집 이력, 신고·숨김·운영자 조치 범위. 내부 직원용인지 외부 고객 공개인지 먼저 결정한다.
- 뉴스레터: 콘텐츠 작성과 외부 대량 발송을 분리한다. 발송에는 F08의 공급자·수신 정책·비용 제한·실패 이력을 적용한다.
- 각 데이터는 조직·작성자·범위·상태·version을 가진다. 지식관리 기반을 공유하더라도 게시글과 상담 사실을 같은 데이터로 취급하지 않는다.
- 완료: 접근 범위, 첨부, 동시 수정, 숨김/삭제의 검색 반영, 예약 발행 중복 방지. 실제 외부 발송은 승인된 대상에 한정한다.

## F13 위젯과 SDK 및 외부 상담 채널

**상태:** 선택 후보, 전체 일괄 구현 지시가 아니다. 공개 링크·최소 브랜딩은 이미 있다.

- 순서 제안: 임베드 위젯 → 고객 API/SDK → 실제 수요가 있는 외부 Adapter 하나. 각 단계별 범위를 사용자에게 확정받는다.
- 위젯은 허용 origin, CSP/iframe, 모바일 크기, 제3자 저장소 제한, 명시적 접수, 브랜딩 상속을 검증한다. 페이지 열람만으로 Queue를 만들지 않는다.
- SDK/API는 공개 session 수명·rate limit·idempotency·version을 문서화한다. 브라우저에 플랫폼 비밀키를 배포하지 않는다.
- 외부 채널은 단순 링크 유입, 외부 접수, 양방향 대화의 범위를 구분한다. 채널별 provider identity를 조직 내 고객 후보와 연결하되 번호/이름만으로 자동 병합하지 않는다.
- Webhook 서명·중복·역순·외부 메시지 ID 매핑·첨부 다운로드 권한·재시도를 구현한다.
- 완료: 다른 사이트/조직의 session 악용 차단, 중복 접수 없음, 공급자 장애 복구, 과거 외부 이벤트 재전송 안전성.

## F14 일반 전화망과 CTI

**상태:** Phase 4 후속. 현재 WebRTC와 콜백 업무 관리는 일반 전화번호로 발신하는 기능이 아니다.

- 실제 전화번호·통신 공급자·SIP 인프라·발신번호·비용·통화/녹음 정책을 확정한 뒤 착수한다. Asterisk 등 특정 제품은 후보이며 확정값이 아니다.
- 전화망 이벤트를 Channel Adapter에서 내부 접수/통화에 매핑한다. 기존 고객·상담·이력·콜백을 별도 PSTN CRM으로 복제하지 않는다.
- 통신사 call ID/leg ID와 내부 원본 접수를 연결하고 중복·역순 이벤트, 착신/발신/응답/종료/이관을 구분한다.
- 실제 발신은 명시적 사용자 행위와 발신 권한·한도·고객 번호 확인을 거친다. 콜백 배정만으로 자동 발신하지 않는다.
- 실패 복구·통화 leg 정리·호전환·녹음 분할/연속성·draining은 공급자별 시험망에서 검증한다.
- 완료: 승인된 시험 번호의 송수신·전환·종료·이력·과금 중복 방지. 플랫폼 API/웹 health를 실제 음성 성공으로 보고하지 않는다.

## D01 고객 병합과 식별 관리

**상태:** 번호 정규화·첫 저장 등록·과거 이력 연결은 존재. 명시적 고객 병합 UI/명령은 후속이다. 근거: 요구사항 69장.

- 중복 후보를 보여주고 직원이 원본/대상·연락처 차이·연관 업무를 검토한다. 같은 번호라는 이유만으로 자동 병합하지 않는다.
- 권한 후보 `customer:merge`, 양쪽 고객과 관련 데이터의 현재 범위를 검사한다. 범위 밖 상담의 존재/본문을 미리보기로 유출하지 않는다.
- 병합 관계/수행자/사유/전후 연결을 기록한다. 상담 원문·작성자·당시 고객 snapshot을 지우지 않는다.
- 활성 통화·미결 이관 중 병합 정책을 정의한다. 초기에는 충돌 위험 구간의 병합을 거부하는 방법을 권장한다.
- 잘못된 병합 대응은 필요하지만 **임의 시점 원클릭 완전 복구는 미확정 제안**이다. 최소한 실행 전 되돌릴 수 있는 범위를 명시하고 원래 연결을 추적한다. 병합 후 새 업무가 생겼을 때 자동 분리를 약속하지 않는다.
- 완료: 같은/다른 번호·이름, 양쪽 버전 충돌, 타 조직 차단, 상담/예약/콜백/녹음/검색 연결 보존, 감사, 복구 가능한 조건 검증.

## D02 조직 수명주기

**상태:** 조직 생성·활성 검사·Membership/직원 삭제는 존재. 조직 중지/종료/보관/삭제의 전체 업무는 미완성이다. 근거: 요구사항 65~67장.

- ACTIVE/SUSPENDED/TERMINATED 등 구체 상태명은 설계 시 정한다. 종료와 데이터 삭제는 별도다.
- 정책표를 먼저 만든다: 상태별 신규 접수/진행 상담/조회/수정/배정/파일/Export/Job/실시간 연결 허용 여부.
- 중지 시 해당 조직만 제한한다. 전역 OIDC 계정이나 다른 조직 업무를 막지 않는다.
- 진행 통화는 drain 또는 즉시 종료 중 승인된 정책에 따라 처리하고 새 배정을 중지한다. 기존 cleanup worker가 중지 조직의 정리를 계속할 수 있어야 한다.
- 상태 변경은 권한·version·사유·감사·중복 명령을 포함한다. 마지막 관리자 보호와 명시적 관리 복구 경로를 유지한다.
- 완료: 중지 후 캐시/WS/파일/Job 우회 차단, 다른 조직 정상, 재활성 상태 복원, 종료 후 데이터 보존, 삭제를 자동 실행하지 않음.

## D03 보존과 삭제 및 익명화

**상태:** 지원 세션 만료·직원 논리 삭제 등 부분 기능은 존재. 전체 데이터 보존 정책과 파생 정리 workflow는 후속이다. 근거: 요구사항 45, 68, 78장.

- 데이터별 정책을 정한다: 고객, 상담, 접수, 녹음, 첨부, transcript, summary, audit, chat, export, 검색/vector, 집계. 보존 일수·법적 근거·계약은 담당자가 확정하며 AI가 임의 법률 기준을 만들지 않는다.
- 삭제 요청→대상 산정/dry-run→승인된 실행→파생/외부 파일 정리→검증/감사 상태를 영속화한다.
- 논리 삭제와 물리 삭제를 구분한다. 다른 기록이 공유하는 첨부·고객을 무조건 cascade 삭제하지 않는다.
- 실패한 외부 파일/검색 삭제는 재시도하고 완료 전 완료라고 표시하지 않는다. 삭제된 문서가 RAG에 남지 않도록 tombstone·조회 차단을 즉시 적용한다.
- 감사에 필요한 최소 증거와 본문·개인정보를 구분한다. 백업 복원 후 삭제 요청이 되살아나는 문제를 정리 절차에 포함한다.
- 완료: 범위 산정·부분 실패/재시작·멱등성·공유 파일 보호·파생 노출 차단·복구 후 재삭제 검증. 실제 데이터 파괴 작업은 승인 범위를 확인한다.

## D04 데이터 내보내기

**상태:** 후속. 근거: 요구사항 79장.

- 최소 대상으로 상담 목록 CSV/고객 데이터부터 선택하고 JSON·첨부·녹음 포함은 별도 범위로 정한다. 포맷은 미확정이다.
- Export Job에 조직·행위자·필터·범위·스키마 버전·진행 상태·만료·fileId를 저장한다. 대량은 지속 worker로 처리한다.
- 요청 시, 실행 시, 다운로드 시 권한을 검사한다. 권한 회수 후 기존 넓은 범위 결과를 재발급하지 않는다.
- 파일은 플랫폼 PRIVATE 저장. 서명 URL 만료/작업 결과 만료와 원본 데이터 보존을 구분한다.
- CSV 수식 실행 위험 문자 처리, 인코딩·시간대·열 설명·null 표현·오류 행을 정한다. 민감정보를 기본으로 전부 포함하지 않는다.
- 완료: 필터와 건수 일치, SELF/TEAM/ORG, 중복 요청, 중단/재시작, 대용량 메모리, 만료/회수 후 다운로드 차단.

## D05 감사와 운영 지원 접근

**상태:** AuditEvent·로그인/관리 이력 API는 존재. 포괄적인 검색·보존·중요 조회/다운로드 감사와 운영 지원 접근 경로는 확인·보완 필요다. 근거: 요구사항 46, 81장.

- 일반 진단 로그와 보안/업무 감사를 분리한다. 감사에는 수행 Identity·조직·대상·명령·결과·시각·추적 ID를 남긴다.
- 기능별 중요한 행위 목록을 정하고 누락을 점검한다. 개인정보 원문·토큰·비밀키를 감사 detail에 복사하지 않는다.
- 기간·수행자·동작·대상·결과 검색과 pagination을 제공하되 감사 조회 자체의 권한도 분리한다.
- 최고관리자 지원 접근이 필요할 때만 목적·대상 조직·기간·진입/종료·권한·감사 계약을 별도로 구현한다. 일반 관리 화면에 무제한 고객 데이터 버튼을 추가하지 않는다.
- 완료: 감사 검색 범위, 직원 삭제 후 표시/식별 추적, 잘못된 요청의 민감정보 비노출, 지원 권한 만료/회수, 중요한 행위 감사 누락 검사.

## H01 태블릿 가운데 패널 스크롤

**상태: 실제 사용자 미해결 확인, 보류. 재개 지시 전 수정하지 않는다.**

재개할 때 확인할 것은 ‘에디터 문서의 내부 스크롤’이 아니라 **고객 정보→분류→에디터→저장 버튼을 담은 두 번째 패널 전체의 스크롤**이다.

- 실제 삼성 브라우저에서 URL/앱 SHA, viewport CSS 크기, DPR, 화면 방향, 데스크톱 사이트 모드, 키보드 표시, 브라우저 확대 상태를 수집한다. 768/1024px 데스크톱 에뮬레이션만 반복하지 않는다.
- `.interaction-editor`에서 부모까지 flex/grid의 min-height, definite height, overflow, dvh/키보드, overlay hit-test, touch-action을 측정한다.
- 기존 수정은 768~1279px에 한정된다. 실제 태블릿이 1280px 이상 CSS 폭인 경우와 포인터 조건을 확인한다. 기기명으로 breakpoint를 추정하지 않는다.
- 짧은/긴 문서, 고객정보 펼침, 가로/세로 회전, 키보드 열린 상태에서 패널 scrollHeight/clientHeight와 터치 스크롤을 검증한다.
- 완료는 실제 기기에서 패널 상단~저장 버튼 접근, 문서 편집·커서·툴바 정상, 중첩 스크롤 최소화, PC/모바일 회귀 없음이다. 사용자 재확인 전 ‘해결 완료’로 보고하지 않는다.

## H02 고객 피드백 경로

**상태: 기획 보류. 이번 자동 콜백에 답변 포털을 추가하지 않기로 범위를 좁혔다.**

향후 재개 시 접수 상태 알림, 연락 시도 결과, 공개용 답변, 고객 재문의 중 무엇을 제공할지 정한다. 내부 상담 본문·직원 메모·녹음·고객 전체 이력을 그대로 공개하지 않는다. 공개 답변 모델과 고객 검증 수단·만료·알림 채널을 따로 설계한다. 연락 시각이 확정되지 않았는데 ‘곧 연락’과 같은 약속을 만들지 않는다.
