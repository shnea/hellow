## 반드시 지킬 기존 요구

1. 역할명이 아니라 **조직 + Permission + Data Scope**로 목록·상세·집계·파일·실시간 접근을 제한한다. SELF 사용자에게 전체 이력을 열지 않는다.
2. 처음 보는 번호가 ‘미등록’이다. 식별 가능한 첫 저장에 고객 등록, 다음 수신에 이전 이력 표시. 식별 실패·취소·미연결도 이력에서 누락하지 않는다.
3. 워크스페이스는 빈 대기열에도 작성 영역을 유지한다. 타임라인 더블 클릭은 공통 읽기 전용 상세 팝업과 인용이며 현재 상담을 교체하지 않는다.
4. 이력·콜백·방문·이관은 목록과 상세 팝업을 사용한다. 팝업 안 후속 작업에서 페이지를 이동해 초안을 잃지 않는다.
5. 수신은 대기 상담사 한 명에게 순차 배정한다. 통화 중 이관 가능, 수락 후 작성 화면 복귀, 양측 참여자의 허용된 이력 조회를 유지한다.
6. 녹음 재생은 독립 권한과 아이콘, 직원 표시는 닉네임(아이디), 템플릿은 기록 제목 오른쪽 칩이다.
7. 신규 음성 요청의 30초 미수락은 단일 미배정 콜백으로 전환한다. 통화 연결 상실의 30초 복귀 유예와 혼동하지 않는다.
8. 기존 원문·고객·소유권·초안·변경 이력을 보존한다. 공급자·가격·보존기간·운영 배포는 미정 사항을 임의 확정하지 않는다.

## 개발 방법

1. `AGENTS.md` → workflow·golden-path → 최신 `docs/handoff.md`를 읽고 실제 코드와 변경분을 확인한다.
2. 기능 하나씩 사용자 흐름·권한·데이터·API·실패/복구·완료 조건을 정한다. 기존 Domain/플랫폼 기능을 재사용한다.
3. 새 DB 변경은 다음 Flyway 번호로 추가한다. 생성/발송은 중복 방지, 수정은 version 충돌 처리, 외부 호출은 잠금 밖 지속 Job으로 처리한다.
4. 정상·타 조직/권한 거부·중복·동시성·재시작을 검사한다. UI는 PC/태블릿/모바일·초안·스크롤을 확인하고 합성 검사와 실제 기기를 구분한다.
5. 문서·handoff 갱신 후 한글 커밋·push한다. 배포는 승인된 환경에서 백업/복원·진행 통화 확인·health·실제 흐름 검증까지 수행한다.
