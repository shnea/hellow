# Hellow 후속 개발 AI 인계서

기준일: 2026-10-04. 대상: 이 저장소를 처음 넘겨받아 남은 기능을 개발하는 AI와 개발자.

빠르게 전달할 때는 [짧은 개발 인계 요약](remaining-work-summary.md)을 사용한다. 상세 구현 시에는 이 문서와 아래 명세를 읽는다.

이 문서는 현재 제품을 보존하면서 전체 서비스의 남은 기능을 이어서 만드는 시작점이다. 기능 개발을 새로 수행한 결과 보고서가 아니다. 다른 AI는 이 파일과 연결된 두 문서를 읽고, 사용자가 지정한 작업 단위를 구현한다.

## 문서 사용 순서

1. 이 문서에서 현재 상태·사용자 확정 요구·작업 순서를 읽는다.
2. [남은 기능 상세 명세](remaining-feature-specs.md)에서 맡은 작업의 데이터·API·화면·권한·완료 조건을 읽는다.
3. [개발 검증 및 배포 인계](development-acceptance-runbook.md)에서 회귀 검사·실기기 검사·배포 경계를 확인한다.
4. 저장소의 실제 코드·현재 Git·최신 [작업 인계](handoff.md)를 다시 확인한다. 이 문서 이후 다른 개발자가 바꾼 사항은 덮어쓰지 않는다.

## 1 현재 제품과 사실의 기준

### 제품 정의

Hellow는 범용 B2B 멀티테넌트 상담·컨택센터 CRM SaaS다. 고객 웹 요청 → 한 상담사에게 배정 → 고객 식별과 이전 이력 확인 → 음성 상담/기록 → 콜백·예약·이관 → 이력·통계의 흐름을 다룬다. 업종 전용 도메인을 Core에 넣지 않는다.

### 상태 표기의 의미

| 표기 | 의미 |
| --- | --- |
| 구현·개발 반영 | 코드와 개발 배포가 존재한다. 모든 실제 기기·운영 수락까지 끝났다는 뜻은 아니다. |
| 사용자 확인 | 실제 사용자 대화에서 동작 확인을 받았다. 확인한 경로에 한정한다. |
| 구현 필요 | 실제 업무 기능이 없거나 메뉴/기반만 있다. |
| 검증 필요 | 구현을 다시 만들지 않고 재현·검사 후 결함만 수정한다. |
| 보류 | 사용자 재개 지시 전에는 작업하지 않는다. |
| 설계 제안 | 구현 출발점이며 기존 계약이나 사용자 확정 사항을 덮어쓰지 않는다. |

### 현재 기준점

- 개발 앱: `aea94bf`, 2026-10-04 API 08:17:25·웹 08:17:08 KST 반영. F01 통계·차트를 포함하며 배포 증거와 권한 부여 잔여는 [최신 인계](handoff.md)를 확인한다. 이 배포 기록 문서의 커밋은 실행 이미지 SHA와 별도다.
- DB: Flyway V21. 기존 migration 파일을 수정하지 말고 실제 HEAD의 다음 번호를 사용한다. 병렬 작업이 있으면 번호 충돌을 먼저 해결한다.
- 최근 검증: F01 Java21 전체 build에서 158건 통과·별도 PostgreSQL fixture9건 통과, 프런트 전체146건 및 최종 관련8건, lint·TypeScript·production build, 합성 브라우저5개 viewport·22장. 개발 배포에서 새 백업/복원과 기존28개 테이블 보존을 재확인했다. 개수는 당시 결과이며 미래 작업의 고정 기준이 아니다.
- 개발 DB 백업 복원과 기존 전체 행/열 hash 보존을 확인했다. 운영 NAS에 같은 버전이 배포되었다는 의미는 아니다.
- 사용자는 실제 LTE 통화 연결과 녹음 저장 성공을 확인했다. 따라서 이 두 기능을 통째로 미구현으로 판단하지 않는다.
- **태블릿 가운데 패널 스크롤은 사용자가 실제로 안 된다고 다시 확인했다. 미해결이며 사용자가 나중에 해결하자고 보류했다.** 이전 에뮬레이션 검사 통과를 실제 해결 증거로 쓰지 않는다.
- 이 문서는 소스·최신 인계·요구사항을 대조한 개발 계획이다. 저장소 전 영역의 신규 통합 테스트나 운영 보안 감사를 수행한 결과는 아니다.

### 문서가 서로 다를 때

사용자의 최신 확정 요구를 우선한다. 현재 구현 여부는 최신 코드·배포 증거·사용자 확인으로 판단한다. 제품 의도는 [요구사항정의서](../요구사항정의서.md)와 golden-path를 따른다. 과거 진행표의 오래된 ‘미구현’ 문구만 보고 기능을 재작성하지 않는다. 코드가 요구를 어기면 코드가 맞다고 간주하지 말고 결함으로 기록한다.

특히 [과거 진행표](mvp-progress.md), [단계별 범위](../skills/golden-path/references/domains/02-scope.md), 과거 검증 표에는 관리자·분류·템플릿·이관·녹음 구현 이전 상태가 남아 있다. 아래 현황과 최신 인계를 함께 읽는다.

## 3 절대 유지할 사용자 확정 요구

### 고객과 상담

1. ‘미등록’은 처음 보는 번호 또는 식별 실패 표시다. 별도 열등한 고객 유형이 아니다. 식별 가능한 첫 상담을 저장하면 고객으로 등록하고 다음 수신에 이전 상담 이력을 보여준다.
2. 이름·번호가 잘못됐거나 같은 번호의 다른 사람일 수 있다. 직원이 확인해 수정하며 근거 없이 자동 병합하지 않는다.
3. 식별되지 않은 접수, 기록을 저장하지 않은 문의, 취소·미연결도 권한 안에서 이력에 나타난다.
4. 완료한 상담도 권한 안에서 수정하고 변경 전 본문·수행자·시각을 남긴다. 통화 종료와 상담 완료는 별개다.

### 화면과 업무 흐름

5. PC 상담 워크스페이스는 대기열 / 작성 패널 / 통합 타임라인·후속 요청의 3단 문맥을 유지한다. 접수가 없어도 작성 영역을 숨기거나 ‘대기열에서 선택’만 표시하지 않는다.
6. 오른쪽 타임라인 단일 클릭으로 작성 중 상담을 교체하지 않는다. 더블 클릭 시 상담이력과 같은 상세 컴포넌트를 읽기 전용으로 열고 인용 버튼을 제공한다.
7. 내가 조회 가능한 타인의 상담도 인용할 수 있다. 원문 수정 권한과 내 상담에 인용하는 권한을 혼동하지 않는다.
8. 상담이력·콜백·방문·이관은 목록 중심이다. 더블 클릭 또는 명시적 상세 버튼으로 팝업을 열며 워크스페이스를 복제한 거대한 에디터 화면을 만들지 않는다.
9. 상세 안의 콜백·방문·이관은 내부 팝업으로 이어지고 원래 필터·페이지·스크롤·초안을 보존한다. 설정도 같은 앱 내 메뉴 이동이다.
10. 상담 중 호전환할 수 있어야 한다. 필요하면 임시 저장하고 진행하며 상담 완료를 선행 조건으로 두지 않는다. 이관 수락 확정 후 팝업을 닫고 워크스페이스 작성으로 들어간다.
11. 태그는 상담 분류에 둔다. ‘상담 기록 작성’ 오른쪽에 자주 사용하는 템플릿 칩을 둔다. 에디터에 태그/템플릿을 다시 별도 선택 폼으로 만들지 않는다.
12. 직원 표시는 저장된 `닉네임(아이디)`가 기본이다. UUID·플랫폼 subject를 고객용/일반 업무 화면에 대신 표시하지 않는다.
13. 녹음은 접근 가능한 이름·툴팁이 있는 아이콘으로 제공한다. 녹음이 있으면 상담이력과 워크스페이스에서 같은 권한으로 재생한다.
14. PC·태블릿 수신 상태는 칩, 좁은 모바일은 select를 사용한다. 빈 공간과 큰 설정 카드로 PC 정보 밀도를 낮추지 않는다.

### 권한과 통화

15. ‘관리자라서 전체’라는 분기를 금지한다. Permission과 Data Scope로 메뉴·목록·상세·파일·집계·실시간 전송을 모두 제한한다.
16. SELF 범위만 있으면 전체 상담이력 메뉴를 보이지 않는다. 대기열에서도 범위 밖 과거 상담을 보이지 않는다. 이관 참여자의 명시적 읽기 관계는 유지한다.
17. 조회 범위와 수신 배정은 별개다. 대기 상담사 모두에게 뿌리지 않고 가능한 한 명에게 순차 제안한다.
18. 음성 수신 가능 전환 시 마이크 준비를 확인한다. 고객 호전환 때 기존 마이크·연결을 불필요하게 재생성하지 않는다.
19. 통화 종료 버튼은 즉시 종료한다. 브라우저 종료/연결 상실은 서버 관찰 기준 30초 복귀 유예를 적용하고 시작 시각을 유지한다. 서버 Media 조회 장애만으로 종료하지 않는다.
20. 신규 음성 요청 전체의 30초 미수락 자동 콜백과 상담사별 제안 시간 제한, 연결 상실 30초 유예는 **서로 다른 타이머**다.
21. 자동 콜백은 미배정으로 만들고 권한자가 한 명에게 배정한다. 별도 수락 절차와 연락 시각 약속을 추가하지 않는다. 팀 없는 미배정 건을 SELF/TEAM에 전체 공개하지 않는다.

세부 계약: [상담·녹음](consultation-history-recordings.md), [이관](work-transfer.md), [콜백](followup-scheduling.md), [배정](contact-routing.md), [고객 진입](public-support.md). 연결된 과거 문구와 충돌하면 위의 최신 사용자 요구와 현재 구현을 대조한다.

## 5 전체 남은 작업과 권장 순서

순서는 제안이다. 사용자가 지정한 작업을 우선하며 이 문서만으로 전체 기능의 구현·비용 사용·운영 배포가 자동 승인되지는 않는다.

| 단계 | ID | 작업 | 상태·의존성 |
| --- | --- | --- | --- |
| 구현·개발 반영·수락 잔여 | F01 | 상담사 현황·기본 대시보드·기본 통계 | 권한별 API/화면·추이/분포 차트 구현. [계약](consultation-reporting.md)·[최종 인계](handoff.md) 확인. 개발 `aea94bf` 반영. 기존 계정 권한 부여·실기기 수락 잔여 |
| 운영 기반 병행 | O01 | 로그·추적·지표·알림·버전 | Health 일부 존재, 전체 운영 체계 구현 필요 |
| 핵심 채널 | F02 | 고객 실시간 채팅 | 사용자 확정 후속. 기존 온라인 문의와 호환 |
| 지식 기반 | F03 | 지식관리·검색 | 확정 후속. AI 없이도 사용할 수 있게 구현 |
| 음성 활용 | F04 | STT·상담 요약 | 녹음 저장 재사용. Provider·비용 정책 확정 필요 |
| AI 지원 | F05 | AI 정책·도우미·RAG·Action | F03/F04와 연계하되 단계별 도입 |
| 직원 협업 | F06 | 조직 내부 채팅 | 고객 채팅의 인증 모델과 구분 |
| CRM 확장 | F07 | 사용자 정의 필드 | 조직 오버라이드 기반 재사용 |
| 외부 연락 | F08 | SMS·이메일·카카오 | 공급자·발신 계정·비용 정책 필요 |
| 운영 관리 | D01~D05 | 병합·수명주기·보존/삭제·Export·감사 | 실제 정책 확정 후 파괴적 행위 구현 |
| 고급 기능 | F09~F11 | 전문 분야 배정·시나리오·고급 통계 | 기본 기능 안정화 뒤 |
| 조직 콘텐츠 | F12 | 공지·커뮤니티·뉴스레터 | 후속 단계. 최소 범위 별도 선택 |
| 선택 확장 | F13 | 위젯·SDK·외부 상담 채널 | 후보. 전체 동시 구현 아님 |
| 전화망 확장 | F14 | SIP·CTI·일반 전화 수신/발신 | 별도 인프라·계약 필요한 Phase 4 |
| 제품 공개 | O02~O04 | NAS 배포·백업/복구·성능/장애 검증 | 운영 공개 전 필요한 수준부터 |
| 보류 | H01/H02 | 태블릿 패널 / 고객 피드백 경로 | H01 재현된 결함, H02 기획 보류 |

핵심 MVP 잔여는 F01의 서비스 반영·실제 수락과 O01, 기존 업무의 실제 수락·운영 준비다. F01 코드를 다시 만들지 않는다. 나머지 모든 후속 기능을 MVP 출시 조건으로 묶지 않는다. 청구/요금제 구현은 현재 상세 확정이 없어 임의 추가하지 않는다.

## 6 다른 AI에 바로 전달할 시작 프롬프트

아래를 복사하고 작업 ID만 바꾸면 된다. 저장소 접근 권한이 있는 AI를 전제로 한다.

```text
Hellow 저장소에서 후속 개발을 이어서 수행해 주세요.

먼저 AGENTS.md, skills/workflow/SKILL.md, skills/golden-path/SKILL.md,
docs/handoff.md, docs/ai-development-handoff.md를 읽으세요.
이어서 docs/remaining-feature-specs.md와
docs/development-acceptance-runbook.md에서 맡은 범위를 읽으세요.

이번 작업 ID: F02 (사용자가 다음 신규 구현을 지정할 때)
이번 작업 범위: 기존 온라인 문의의 고객 실시간 채팅 확장.
F01 코드 구현은 완료했으므로 먼저 handoff의 서비스 반영·실제 수락 잔여를 확인하세요.
다른 후속 기능 전체를 동시에 만들지 마세요.

문서 작성 이후 HEAD가 바뀌었을 수 있으므로 실제 코드와 Git 상태를 확인하세요.
과거 진행표만 보고 관리자/템플릿/녹음/이관/자동 콜백을 재작성하지 마세요.
확정 요구와 설계 제안, 미정 정책을 구분하세요.
태블릿 가운데 패널 스크롤과 고객 피드백은 보류 상태입니다.

조직 + Permission + Data Scope를 목록/상세/집계/파일/실시간 모두에 적용하세요.
역할 이름으로 전체 조회를 허용하지 마세요.
기존 상담·통화·초안·이관 참여자 조회·독립 녹음 권한을 보존하세요.

구현 전에 변경 경계와 완료 조건을 짧게 설명한 뒤 진행하세요.
정상/거부/동시성/복구를 검증하고 UI는 프로젝트 Impeccable 절차를 따르세요.
실사용·운영 데이터를 테스트용으로 변경하지 마세요.
외부 공급자 사용·유료 비용·운영 배포는 현재 승인 범위를 확인하세요.
검증 후 계약 문서와 handoff를 갱신하고 한글 커밋·push하세요.
배포한 경우에만 배포 환경/버전/health/복원 증거를 보고하세요.
미검증 항목을 완료라고 말하지 마세요.
```

## 7 개발 결과 보고 형식

각 기능을 끝낼 때 다음을 남긴다.

1. 작업 ID, 사용자 흐름과 구현 범위.
2. 코드·migration·새 권한·기존 데이터 영향.
3. 정상/권한 거부/경합/복구 검증 결과와 증거 위치.
4. 실제 브라우저·기기·네트워크에서 확인한 범위와 미확인 범위.
5. 커밋, push, 배포 여부와 정확한 환경·버전.
6. 다음 작업과 사용자 결정이 필요한 항목.

전체 완료율을 근거 없이 숫자로 만들지 않는다. 특정 테스트 통과를 서비스 전체 완료로 확대하지 않는다.
