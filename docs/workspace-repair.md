## 첫 구현 단위의 경계

### 워크스페이스·상담이력 화면 계약 (2026-10-03 추가)

- PC 워크스페이스는 처리 대기열/상담 편집기/통합 타임라인·후속 업무의 3단 구성을 유지한다. 대기열의 과거 기록 선택은 가운데 편집기를 사용한다. **오른쪽 통합 타임라인은 단일 클릭으로 현재 상담을 바꾸지 않고 더블 클릭하면 상세 팝업을 연다.** 현재 상담의 통화·고객·초안은 유지한다. 이전 기록 수정은 대기열/상담이력에서 수행하며 타임라인 미리보기와 구분한다.
- 상담이력 메뉴는 독립 페이지이며 처리 대기열을 표시하지 않는다. 고객·상담 이력 모두 저장 기록과 기록을 저장하지 않은 접수(취소·미연결 포함)를 함께 조회한다. 식별 실패가 이력 제외 조건이 되지 않는다.
- **2026-10-04 사용자 정정:** 미등록은 별도 관리 유형이 아니라 처음 온 번호 또는 식별 실패 표시다. 식별 가능한 첫 상담 저장 시 고객을 자동 등록하고 같은 번호의 다음 수신에서 기존 고객과 이력을 연결한다. 직원이 이름·번호를 확인해 수정할 수 있고 이력은 유지한다. 같은 이름·번호의 중복 고객 항목은 기존 항목을 삭제하지 않고 이력을 함께 조회한다. 다른 이름의 중복 번호는 정확한 이름으로 구분되지 않으면 직원 확인 대상으로 남긴다. 공개 고객 세션에는 기존 고객 정보와 CRM 이력을 노출하지 않는다.
- 워크스페이스는 접수/선택이 없어도 고객 정보·에디터·타임라인·후속 업무 영역을 유지한다. 처리 대기열의 배정 이력은 표시하지 않는다. 완료 뒤에도 같은 화면에서 편집하고 수정 전 본문·수정자·시각을 변경 이력에 남긴다.
- 온라인 문의 접수의 실시간 채팅 전환은 후속 작업으로 확정했다. 이번 우선 복구에서 채팅을 구현한 것으로 취급하지 않는다.
- 태그는 상담 분류 영역에만 둔다. 기록 제목 오른쪽의 `자주 사용하는 템플릿 :` 칩으로 활성 템플릿을 삽입하며 작은 화면에서는 칩 영역을 스크롤할 수 있다.

- API의 조직·Permission·Data Scope 검증은 유지한다. 정상 로그인 뒤 하위 API의 403을 로그인 만료로 취급하지 않는다.
- **2026-10-04 프로필 표시:** 좌측 하단 로그아웃 칩과 펼친 메뉴에는 검증된 이름만 표시한다. `/api/me.displayName`은 nickname/name에서 가져오며 loginId를 붙이거나 대체 이름으로 쓰지 않는다. 긴 이름은 칩 안에서 생략하고 툴팁·메뉴에 전체 이름을 제공한다. 다른 업무 표시명의 기존 이름/아이디 형식은 유지한다.
- 갱신은 기존 public-client PKCE 계약에서 받은 refresh token을 사용한다. 한 탭의 동시 요청은 갱신을 공유하며, 로그아웃/다른 로그인 중 늦게 온 응답이 세션을 복원하지 않는다. 공급자 일시 장애 때 자격 증명과 초안을 삭제하지 않는다.
- 초안은 issuer+subject+organization으로 구분한 sessionStorage에 보관한다. 새로고침·인증 왕복을 지원하며 탭 폐쇄 후 영구 보관을 약속하지 않는다. 복원 초안은 현재 서버 권한/버전을 다시 확인하고 자동 덮어쓰기하지 않는다. 읽을 수 없는 저장소는 보존하고 오류를 표시한다.
- 완료·취소 조회는 기존 QueueView와 조직/행 범위를 사용한다. 접수 capability는 응답에 포함하지 않는다. 상담 기록이 있으면 별도 기록 권한을 확인하는 상세 화면으로 열고, 기록 없는 취소는 접수 정보만 보여준다.
- 실제 서비스 컨테이너/DB/인증 서버 설정은 이 단위에서 변경하지 않았다. Docker 검수 이미지와 합성 API의 브라우저 검증은 개발 서비스 반영과 다르다.

## 검증 증거

- 브라우저: Chrome headless 1280×800, 768×1024, 375×812. 주요 상담 상단/저장 버튼 위치/설정 화면 9장. `output/workspace-repair-ui/proof.json`에서 가로 넘침 없음, 저장 버튼의 실제 hit-test 도달, page error 없음 확인. API는 합성 fixture이며 iOS/Android 실기기·실음성 성공 증거가 아니다.
- Impeccable context는 기존 세션 1회 결과를 사용했다. detector 1회에서 기존 QueuePanel의 굵은 한쪽 테두리 경고를 1px로 수정했다. 전용 reviewer type이 없는 harness이므로 fresh 일반 agent에 shipped degraded reviewer 역할을 적용했다. 결과는 `output/workspace-repair-finish-review.md`에 있다.
- 자동 검사·커밋·반영 결과는 [작업 인계](handoff.md)에 최신 실행 기준으로 기록한다.

## 통화·녹음 후속 구현 근거

플랫폼의 공개 [로그인 계약](https://platform.shnea.kr/integrations/auth.md)과 [파일 계약](https://platform.shnea.kr/integrations/file.openapi.json)을 조회했다. 플랫폼은 저장을 제공하며 통화 녹음 생성은 Hellow의 책임이다. PRIVATE 파일의 짧은 보기 URL 대신 fileId를 영속 연결한다.

2026-10-04 개발 LiveKit 1.13.7에 Redis와 Egress 1.14.1을 추가하고 실제 합성 음성을 플랫폼에 저장·재생했다. 현재 화면/권한/저장 계약은 [상담 이력·녹음](consultation-history-recordings.md)을 따른다. NAT/ICE·TURN 도달성과 물리 기기의 실제 대화 수락은 합성 검사와 구분한다.
