# 조직 내부 채팅·지식관리 계약

## 범위와 선택

2026-10-04 사용자 요청으로 두 기능만 신규 개발한다. 각각 `조직 내부 채팅`·`지식관리`를 상담 이관·콜백·방문 예약과 같은 좌측 메뉴로 추가한다. 사용자가 말한 탭은 이 메뉴를 뜻한다. 기존 상담/통화/초안을 유지하며 목록은 My 상담 이력 디자인, 대화는 상대 왼쪽/내 메시지 오른쪽을 따른다. 이 구성은 기존 사용자 디자인 요청과 F03/F06 명세에 고정된 일반 확장이므로 새 시각 정체성/구조 선정 절차로 확대하지 않는다.

- 지식관리: 문서/FAQ, 제목·분류·본문 검색, 비공개 초안, 명시적 게시/보관, SELF/TEAM/ORGANIZATION 공개 범위, 안정적인 문서 링크, 편집 및 버전 이력, PRIVATE 첨부. 게시된 원문을 편집해도 새 초안을 게시하기 전까지 독자가 보는 게시 버전은 유지한다. 보관하면 검색·원문·첨부 열람도 즉시 현재 권한으로 제한한다. 기존 SHNEA Editor와 PostgreSQL 검색을 사용하고 AI/외부 검색 서비스를 추가하지 않는다.
- 내부 채팅: 같은 조직의 활성 직원끼리 1:1 및 명시적 참여자 그룹, 방 만들기/목록, 초대·퇴장·참여자 제거, 저장 메시지·읽음·미읽음, PRIVATE 첨부와 재접속/같은 UUID 재시도. 초대된 참여자는 방의 저장 대화를 읽을 수 있다. 퇴장/제거 후 새 열람·전송·첨부·구독을 차단하며 과거 메시지는 보존한다. 그룹 만든 사람이 참여자를 관리한다. 관리자가 방 참여 권한 없이 대화를 열람하지 않는다.
- 새 권한은 knowledge:read/write/publish, internal-chat:read/write. 현재 활성 Membership과 기능 권한을 매 명령·조회·전달에서 검사한다. 지식의 공개 범위와 기능 Data Scope를 모두 적용하고 초안은 작성/게시 가능한 직원만 읽는다. 내부 채팅은 기능 권한과 명시적 방 참여를 경계로 삼는다. 채팅 권한의 SELF/TEAM 값으로 다른 직원의 같은 방 메시지를 숨기지 않으며, 조직 전체 권한도 비참여 방 열람을 허용하지 않는다. 조직의 현재 채팅 조회 권한을 가진 직원만 참여자 후보로 제공한다. 기존 직원/역할에 새 권한을 자동 부여하지 않는다.
- 파일은 기존 플랫폼 PRIVATE·보존 정책·청크 업로드를 재사용하며 50MiB 한도다. 저장 관계/같은 UUID·SHA256을 확인하고 티켓은 해당 문서/방 접근을 재검사한다. 첨부는 문서 또는 메시지에 명시적으로 연결되며 공유 URL/파일 공급자 ID를 목록에 노출하지 않는다. 보존기간과 물리 삭제는 현재 공급자 계약을 따르고 별도 삭제 정책을 임의 확정하지 않는다.
- 외부 알림 발송·푸시·조직 간 채팅·AI/STT·보류 태블릿 스크롤은 이번 범위에 포함하지 않는다. 탭 안 미읽음 표시를 제공한다.

## 저장·동시성·한도

- V25는 새 테이블6개만 추가한다. 기존 고객 대화·상담·파일·권한 테이블을 변경하지 않는다. 쓰기는 조직 잠금 이후 현재 권한을 다시 확인하고 문서/방의 version 충돌은409로 반환한다. 변경 전 읽은 Membership 캐시를 다시 사용하지 않는다.
- 지식 목록과 버전 이력은30건씩 조회한다. 문서 JSON은200,000자·깊이64, 제목200자·분류100자, 명시적 첨부50개다. 게시 버전의 본문·종류·공개 범위·첨부를 별도로 유지한다. 게시 전용 권한은 게시·보관·이력 확인만 허용하며 본문 작성 권한을 대신하지 않는다. TEAM 공개는 작성자 팀과 현재 독자 팀을 확인한다.
- 방 참여자는 본인을 포함해 최대50명, 메시지는10,000자 또는 첨부 최대5개, 기록 조회는100건씩이다. 1:1 방은 직원 쌍당 하나이며 퇴장 후 다시 열 때 요청자 본인만 재참여한다. 상대방을 자동으로 다시 초대하지 않는다. 그룹 생성자는 다른 참여자를 모두 제거한 뒤 퇴장한다. 관리자 이전 기능은 이번 범위에 포함하지 않는다.
- 메시지와 파일 업로드는 요청 UUID·내용/바이트 검사를 통해 같은 응답을 재현한다. 다른 내용으로 UUID를 재사용하면409다. 방 sequence와 읽은 sequence를 영속 저장하며 읽음은 뒤로 가지 않는다. 화면이 활성화되고 브라우저가 보이며 최신 기록까지 내려간 경우에만 읽음 처리한다.
- 초안은 조직·검증된 issuer/subject·문서 또는 방별 sessionStorage에 보존한다. 전송 파일 Blob과 요청 UUID는 IndexedDB에 먼저 보관한다. 전송 결과가 불명확한 동안 같은 본문/첨부로 재시도하며 방 퇴장을 막는다. 조직·권한 변경은 해당 컴포넌트를 다시 구성한다. 기존 상담 컴포넌트는 새 메뉴 전환으로 제거하지 않는다.
- 파일 공급자 저장은 기존 PRIVATE 보존 계약을 재사용한다. 지식 첨부는 게시된 스냅샷의 파일만 독자에게 허용한다. 방의 미전송 첨부는 업로드한 직원만 열 수 있다. 조회 티켓은 현재 권한·참여를 확인하고 http/https 원본·미리보기·썸네일만 반환한다. 일반 파일은 원본 열기를 제공하며 문서 내 미디어는 SHNEA Editor 어댑터를 이용한다.

## 검증과 인계

타 조직/비참여자/현재 권한 회수, SELF·TEAM 공개 범위, 초안과 게시 원문 분리, 버전 충돌·검색/파일 경계, UUID 중복·바이트 변경·동시 전송/퇴장, 읽음 단조 증가·재시작 보존을 검사한다. 실제 PostgreSQL 및 두 브라우저의 직원 흐름·탭/초안 보존·desktop/mobile·빈/오류/권한 상태를 검증하고 UI finish reviewer/documenter를 적용한다. 개발 반영은 신규 백업/복원·활성 상담 drain·모든 기존 데이터/권한 보존 후 수행한다. 검수용 권한/계정은 격리 DB에만 만들며 실제 사용 계정의 권한 설정과 물리 기기 수락은 구분한다.
