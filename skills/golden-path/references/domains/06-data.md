# 데이터·파일·상태 관리

필요시 확인: 데이터·파일·저장·삭제·동시 수정·이관을 다룰 때.

적용 범위: 조건부. 데이터를 저장·교환하거나 상태·파일을 다룰 때 적용한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 데이터 의미와 소유권 | 핵심 개체·관계, 누가 소유·변경하는지 | 확정: 업무 Entity의 Organization 경계, Identity/Membership 분리, Interaction/배정 시도/Consultation 구분. Contact Center가 실시간 Agent 상태의 진실 원천. 다른 서비스 소유 데이터는 API/Event로 변경. |
| 저장 방식 | 메모리·파일·DB·외부 저장소, 선택 이유 | 확정: PostgreSQL 업무 데이터. 파일은 SHNEA fileId 참조, 대용량 녹취는 DB Binary로 저장하지 않는다. 검색·Vector·통계·AI 결과는 원본과 구분하고 가능한 경우 재생성 가능하게 한다. |
| 무결성과 동시 변경 | 필수값·중복·트랜잭션·동시 수정 충돌, 필요한 수준 | 확정: 원자적 상담사 확보, 상태 전이 검증, 중복 명령·오래된 Event 차단. 고객 자동 매칭 근거가 부족하면 병합하지 않고 병합 시 연관 이력과 수행자 추적성을 보존한다. |
| 수명과 이동 | 보관·삭제·내보내기·가져오기·기존 데이터 이관 | 확정: 조직 중지·종료와 삭제, Membership 비활성화와 User 삭제를 구분한다. 마지막 Admin 보호, 초대 만료·취소·재초대 처리. 원본 삭제 시 File/Search/Vector/AI 파생 데이터 추적. 권한·Scope 적용 Export 지원 가능 구조. |
| 파일과 용량 | 형식·크기·저장 위치·접근·업로드 실패 처리 | 확정: 고객·상담 첨부·녹취·Transcript·비공개 문서는 PRIVATE. 열람 전 CRM 권한·업무 소유 관계 확인. default 보존 코드를 영구 보존으로 가정하지 않는다. 크기·보존기간 미정. |
| 형식 변경 | 스키마·파일 형식 버전, 이전 데이터·클라이언트 호환 방법 | 확정: Expand → Migrate → Contract 우선 검토, 마이그레이션 재실행·실패 복구·구버전 호환. 서버/DB UTC 우선, 미래 예약의 시간대 의미와 통계 일/주/월 경계 유지. |
