# 보안·인증·권한·개인정보

필요시 확인: 입력 경계·인증·권한·공유·민감정보를 다룰 때.

적용 범위: 입력·비밀정보 처리는 해당 경계에서 검토한다. 계정·역할·개인정보 절차는 실제 필요할 때만 적용한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 접근 범위 | 로컬·내부·공개 여부, 외부 입력과 신뢰 경계 | 확정: DB·Cache·Event·Job·Search·Vector·File·WebSocket·실시간/임시 상태 전부 조직 격리. URL/Header/AI Context/Trace Metadata는 권한 근거가 아니며 서버가 검증한 Context만 전파한다. |
| 인증 | 로그인 필요 여부, 기존 인증 서비스, 세션·계정 수명 | 확정: SHNEA OIDC subject와 CRM User 연결. 자체 비밀번호 인증 금지. 조직 없는 가입 허용·다중 Membership 가능 구조. 고객용 세션과 직원 인증 분리. |
| 권한·공유 | 누가 무엇을 읽고 변경하는지, 사용자·조직 간 데이터 분리 | 확정: 동적 Role과 Permission + SELF/TEAM/ORGANIZATION Scope, 메뉴와 Backend 모두 검증. Membership 회수 즉시 해당 조직 차단. Platform Super Admin도 업무 데이터 무제한 접근 불가; 명시적 지원 접근·감사 필요. |
| 개인정보·민감정보 | 필요한 수집 범위, 보관·삭제·노출 방지 | 확정: 최소 권한·마스킹·보존/삭제 정책. 비밀값·전체 Token·민감 원문을 일반 로그에 저장하지 않는다. RAG 자료는 데이터이며 지시로 취급하지 않는다. AI 권한은 사용자 이하, 고위험 Action 확인과 감사. |
| 설정·비밀값 | 환경별 설정, 비밀값 보관·주입, 로그에서 제외할 값 | 확정: Provider Credential 암호화, 플랫폼 서버 키는 서버 전용. .env.dev/.env.prod는 각각 SOPS + age 암호화 후 Git 보관. 개인키·평문 제외; 공개키·주입 방식 미정. |
