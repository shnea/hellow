# 보안·인증·권한·개인정보

필요시 확인: 입력 경계·인증·권한·공유·민감정보를 다룰 때.

적용 범위: 입력·비밀정보 처리는 해당 경계에서 검토한다. 계정·역할·개인정보 절차는 실제 필요할 때만 적용한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 접근 범위 | 로컬·내부·공개 여부, 외부 입력과 신뢰 경계 | 확정: DB·Cache·Event·Job·Search·Vector·File·WebSocket·실시간/임시 상태 전부 조직 격리. URL/Header/AI Context/Trace Metadata는 권한 근거가 아니며 서버가 검증한 Context만 전파한다. |
| 인증 | 로그인 필요 여부, 기존 인증 서비스, 세션·계정 수명 | 확정: SHNEA OIDC subject와 CRM User 연결. 자체 비밀번호 인증 금지. 조직 없는 가입 허용·다중 Membership 가능 구조. 고객용 세션과 직원 인증 분리. |
| 권한·공유 | 누가 무엇을 읽고 변경하는지, 사용자·조직 간 데이터 분리 | 확정: 동적 Role과 Permission + SELF/TEAM/ORGANIZATION Scope, 메뉴와 Backend 모두 검증. Membership 회수 즉시 해당 조직 차단. Platform Super Admin도 업무 데이터 무제한 접근 불가; 명시적 지원 접근·감사 필요. |
| 개인정보·민감정보 | 필요한 수집 범위, 보관·삭제·노출 방지 | 확정: 최소 권한·마스킹·보존/삭제 정책. 비밀값·전체 Token·민감 원문을 일반 로그에 저장하지 않는다. RAG 자료는 데이터이며 지시로 취급하지 않는다. AI 권한은 사용자 이하, 고위험 Action 확인과 감사. |

## 관리자 및 추가 기능의 접근 경계

- 현재 플랫폼 프로젝트 realm의 access token은 `aud=account`, `azp=app`, `typ=Bearer`로 발급된다. Hellow API는 플랫폼 issuer의 서명·만료, 설정된 client와 일치하는 `azp`, Bearer token type, 해당 audience를 함께 검사하고 `(issuer, sub)`의 활성 Membership·Permission으로 업무 접근을 제한한다. ID token이나 다른 client 토큰은 받지 않는다. 플랫폼에서 전용 API audience가 제공되면 이를 설정해 해당 audience도 확인한다. 이 계약은 실제 로그인·권한 회수 검증으로 수락한다.
- 최고관리자 식별은 `ADMIN_OIDC_ISSUER`와 `ADMIN_OIDC_SUB`를 함께 검증한다. issuer만으로 최고관리자를 판별하지 않는다. 기본 issuer 주소는 인증 서비스 계약 확인 후 정하며 일반 계정을 최고관리자로 만드는 기본값을 두지 않는다. 현재 두 설정은 비어 있으면 거부한다.
- 최고관리자는 공통 설정과 대상 조직의 관리자 기능을 수행할 수 있다. 조직별 작업은 대상 조직을 명시하고 수행자·대상·변경을 감사 기록으로 남긴다. 조직관리자는 자기 조직의 범위를 벗어나거나 최고관리자 권한을 부여할 수 없다. 마지막 조직관리자 제거 방지와 안전한 관리자 이관을 지원한다.
- 최고관리자의 조직 관리 권한을 고객 업무 데이터 무제한 접근으로 확장하지 않는다. 내용 조회·청취 등이 필요한 지원 접근은 원문 81장의 명시적 접근·감사 기준을 적용한다.
- 상담 상태 모니터링, 상담 내용 열람, 통화 청취는 독립 권한이다. 조직/팀 Scope를 서버에서 확인한다.
- 조직 공유 템플릿 관리와 개인 템플릿 관리 권한을 구분한다. 개인 템플릿은 작성자 소유이며 관리자라는 이유로 자동 열람·수정하지 않는다.
- 지식 원문·파일·검색·Vector·AI 응답에 동일한 조직/Scope 경계를 적용한다. AI는 사용자의 권한을 넘지 않으며 권한 없는 지식을 인용·노출하지 않는다.
- 내부 채팅은 조직과 대화 참여 권한을 확인하며 WebSocket·검색·첨부파일에도 적용한다. 탈퇴·권한 회수 후 접근을 차단한다. 관리자 지위만으로 모든 비공개 대화의 열람권을 자동 부여하지 않는다.
