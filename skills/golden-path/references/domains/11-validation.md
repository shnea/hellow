적용 범위: 공통 정의 항목. 작업 영향에 맞춰 구체화한다.

## 실제 실행 명령

프로젝트에서 사용할 실행·검증 명령을 필요한 작업에 한해 기록한다. 명령이 존재하는 것과 실제 실행 검증이 끝난 것을 구분한다.

| 작업 | 명령·환경 | 확인 결과·제약 |
| --- | --- | --- |
| 서버 테스트 | Java 21/Gradle 8.12.1, `gradle test` (`backend` 디렉터리); PostgreSQL 17.11 분리 DB | 12개 통과. 리뷰 결과에는 당시의 전체 호출 명령이 남아 있지 않으며, 표의 명령은 동일 Gradle 환경에서 재실행할 명령이다. |
| 화면 테스트 | `npm --prefix frontend test` | 8개 통과 |
| 화면 lint·build | `npm --prefix frontend run lint`, `npm --prefix frontend run build` | 모두 통과 |
| Nginx 설정 | 격리된 Nginx 컨테이너 내부 `nginx -t` | 통과. 기존 개발 서비스 reload 없음 |
| 브라우저 저장·복구 | 격리된 합성 JWT·조직·고객 DB와 배포 빌드에서 수동 확인 | 초안 저장·새로고침 복구·우측 이력 상세와 편집기 동시 표시 확인. 실제 운영 인증·데이터 미사용 |
| 문서·참조·요구사항 범위·스킬 해시 | `python scripts/verify-docs.py` | 이전 작업 인계에 통과 기록. 이번 문서 변경 후 재실행 결과도 인계에 기록 |
| Git 형식 | `git diff --check`, staging 후 `git diff --cached --check` | 이전 작업 인계에 whitespace 통과 기록. 이번 변경도 재검사 |
| UI 검토 | Impeccable context·harden·craft-floor 및 detector | 기존 시각 스타일 경고 12개 유지. detector 통과가 아님 |
| 운영 통합 수락 | 실제 OIDC, 권한 배정·회수 후 연결 종료, 파일 보존 정책, 2인 WebRTC, NAS 배포·DB 이관/복구 | 미실행 |

[리뷰 수정 결과](../../../../docs/review-repair.md)에 검증 범위와 남은 수락 조건을 기록했다. 위 결과는 해당 부분 구현의 검증이며 MVP 전체 수락이 아니다.

콜백·방문 일정 서버 단위는 `docker build --target api -t hellow-dev-api:followup-check .`의 Java 21 전체 build/test와 새 통합 17건, 실제 개발 백업의 별도 PostgreSQL V12 복원·기록 보존, 합성 일정 API의 중복/동시 확정·조직 충돌·재배정·재시작 후 진행·실패 재예약/취소를 검증했다. 기존 후속 요청은 실제 DB에 0건이므로 V12 전 합성 legacy 요청/범위를 별도 복원 DB에 넣어 보존을 확인했다. 화면·동시 배포·사용자 수락은 남았으며 상세 증거/이미지/백업은 [인계](../../../../docs/handoff.md)와 [예약 계약](../../../../docs/followup-scheduling.md)에 둔다.

이어서 요청 GET 복원·capability/최소 연락처·대기열 권한 없는 본인 처리 상태 검증을 추가하여 FollowUpIntegrationTest 19건·서버 전체 89건을 통과했다. frontend 전체 70건·lint와 Docker production TypeScript/build를 통과했으며 접수 응답 불명/저장소 실패/동일 ID 복원·409 버전 보존·종료 후 일정만 변경한 초안/담당 이름 보존·권한/조직 변경 차단·완료 기록 재조회/기준 버전 보존을 확인했다. 별도 PostgreSQL/합성 직원의 실제 웹에서 접수→배정→일정 변경→시작→실패→재예약→취소·완료 상담 기록에서 추가 접수와 외부 종료 후 보존을 검수했다. 원본 접수/상담 소유권을 유지했다. 375/768/1280px 캡처·실제 픽셀 크기·모바일 하단 44px/가로 넘침 없음 확인, detector 1회 기존 로고 경고1을 전달했고 독립 리뷰의 날짜 아이콘 대비·일정만 변경한 초안 보존 지적을 해결하여 해당 수정/검토 범위 ship을 받았다. 실제 기기/실계정/음성 수락·동시 배포는 별도이며 [진행표](../../../../docs/mvp-progress.md)와 인계에 갱신한다.

## 근거와 연결

이관 화면 연결용 원본 id 조회·서버 받은/보낸 페이지 필터는 Java 21 전체109건·이관20건을 통과했다. 수락 전 본문 차단·수락 후 현재 담당 조회·고객 조회 권한과 독립한 상담 범위·현재 editable/읽기 회수, 51건 수신의 페이지 보존·동일 subject 다른 issuer/조직 차단을 검증했다. 별도 V14 PostgreSQL의 새 합성 조직/SQL 독립 기록에서도 확인했다. 프런트엔드 UUID 전송 모듈은 전체77건·추가7건·lint·TypeScript noEmit 통과이며 전송 전 보관·GET 우선 복원·동일 본문 재전송·충돌/회수/저장소/응답 이상 때 요청 보존을 검사했다. 아직 사용자 화면 연결·브라우저 검수·개발 동시 배포는 하지 않았고 [인계](../../../../docs/handoff.md)에 다음 단위를 기록했다.

업무 이관 서버는 `docker build --target api -t hellow-dev-api:transfer-check .`의 Java 21 전체107건·새 통합18건을 통과했다. 요청 중복/동시 수락·취소, SELF/팀 하위/조직·다른 issuer, 현재 역할 회수·비활성 담당 복구, 원본 버전/담당/문서 보존, 새 담당 수정과 이전 담당의 새 본문 차단, 원래 접수 첨부 접근, 실시간 대상의 ACD/예약 시작·조직 변경 차단·최종 결과 저장 후 예약 해제와 종료 통화의 이전 참가자 제거 재시도를 포함한다. 참가자 제거는 공급자 mock 검증이며 실제 두 사람 음성을 증명하지 않는다. 개발 DB의 별도 V13/V14 PostgreSQL 복원·건수/원문 hash·권한 범위 보존을 확인했다. 실제 API 수행·재시작 증거, 미배포 및 다음 화면/통화 이관 범위는 [인계](../../../../docs/handoff.md)와 [이관 계약](../../../../docs/work-transfer.md)에 둔다.

## 단계별 수락 검증 기준

2026-10-03 추가 지침의 구현 시 검사: 최고관리자 issuer만 일치하는 일반 사용자 거부, 타 조직 관리 거부·최고관리자 대상 조직 작업 감사, 마지막 관리자 보호, 상태 조회 권한으로 내용/청취 접근 거부, 공통 변경 시 상속 항목만 반영·조직 오버라이드 유지·기본값 복원, 4단계/잘못된 부모 분류 거부, 분류·템플릿 변경 후 과거 상담 보존, 타인의 개인 템플릿 접근 거부. 후반에는 지식/AI 출처의 권한 필터와 채팅 참여·권한 회수·첨부파일 경계를 검증한다. 이 항목들은 지침 확정이며 현재 통과한 검사로 간주하지 않는다.

아래는 단계별 전체 수락 기준이다. 위 표에 통과로 기록한 일부 경로 외에는 미검증이며, 전체 통과로 해석하지 않는다.

| 대상 | 수락 기준 |
| --- | --- |
| 조직 격리·권한 | 타 조직 ID·객체·Cache·Event·Job·파일·WS 경로 접근 거부. Membership 회수 후 기존 연결 포함 접근 차단. 조직 중지는 다른 조직/전역 Identity 차단과 구분 |
| 배정·상태 | 동시 요청이 동일 AVAILABLE 상담사를 중복 확보하지 않음. 이관 수락 경쟁·중복 명령·역순/오래된 Event가 상태를 훼손하지 않음 |
| 고객 진입 | 단순 열람·미리보기·중복 클릭·Webhook 재전송은 중복 업무를 만들지 않음. 연결 준비 전 상담사 점유 없음. 운영시간 외/부재/취소/마이크 거부/연결 실패 안내 |
| 복구·배포 | 브라우저/WS/Media 단절·재시작 후 세션 복구 또는 안전 종료, 중복 활성 없음. Draining/재연결과 Core 조회·저장 보존 검증 |
| 파일·삭제 | PRIVATE 저장·업무 소유 관계 검증·URL 발급 권한 확인. 삭제/익명화 후 검색·Vector·AI 파생 데이터 처리 추적 |
| AI 도입 단계 | RAG 조직/Scope 필터, Prompt Injection에 의한 권한 상승 차단, 고위험 Action 확인·중복 실행 방지. Provider 장애 시 Core 사용 가능, 비용 한도 서버 적용 |
| 운영 데이터 | Backup 파일 존재만 확인하지 않고 Restore 검증. 구·신 앱의 DB/API/Event 호환 및 이관 실패 복구 검증 |
