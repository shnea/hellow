# 외부 연동·인터페이스

필요시 확인: API·파일 교환·외부 서비스 계약과 실패 처리를 바꿀 때.

적용 범위: 조건부. API·파일·메시지·외부 서비스 등 다른 시스템과 연결할 때 적용한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 연동 대상과 책임 | 기존 서비스 재사용, 제공자·소비자, 외부 도구 의존 | 확정: SHNEA OIDC·File·Editor·Job. 첫 실시간 채널 WebRTC. SMS/Kakao/Email과 후속 SIP/CTI는 Adapter 경계. 유입 경로와 실제 Channel, 외부 채팅과 링크 연결을 구분한다. |
| 계약과 형식 | 입력·출력·오류·버전·인증·시간대·단위 | 확정: 실제 SERVICE_INTEGRATION.md와 하위 명세 확인 후 구현. Domain 중심 API, Pagination/Sorting/Filtering/Validation/오류/시간/Request ID 일관화. 구체 형식·버전 미정. |
| 실패와 중복 | 타임아웃·재시도·중복 요청·일부 성공 처리 | 확정: Webhook 서명·인증 검증, 중복·순서 역전·오래된 상태 차단. Event는 사실, Command는 실행 요청. DB/Event 일관성 필요 시 Outbox 등 선택. Provider 장애 격리. |
| 제한과 검증 환경 | 호출량·비용·용량 한도, 개발용 대체 수단·실제 연결 확인 | 확정: Organization 자체 메시지 계정·비용. 외부 Provider 심사·계약·지원 범위는 도입 시 공식 명세 확인. 유료 AI 비용 주체·서버 한도 선행. 실제 연동 테스트는 미실행. |
