# 제약·우선순위·운영 규모

필요시 확인: 일정·비용·규모·호환성·금지 조건이 선택에 영향을 줄 때.

적용 범위: 공통 정의 항목. 선택을 바꾸는 제약부터 확인한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 일정·예산 | 납기, 초기 비용·월 운영비 한도, 유료 서비스 허용 범위 | 미정: 납기·월 운영비·유료 사용 한도. 원칙 확정: 메시지 비용은 Organization 자체 Provider 계정, 유료 AI는 사용 전 비용 주체·서버 한도 설정. |
| 판단 우선순위 | 단순함·속도·안정성·성능·비용 중 충돌 시 무엇을 우선할지 | 확정: 조직 격리·무결성·운영 가능성을 지키면서 단순하고 사람이 추적·수정하기 쉬운 구조를 우선한다. |
| 필수·금지 조건 | 반드시 쓰거나 쓰지 않을 기술·서비스·환경 | 확정: SHNEA 공통 기능 재사용. 업종 전용 Core, Entity별 MSA, 모든 설정의 단일 JSON화, 모든 Domain의 Common Code화, 초기 범용 Builder·전면 Event Driven화를 피한다. |
| 규모·연결 조건 | 예상 사용량·데이터량, 온라인·오프라인, 확인되지 않은 가정 | 미정: 조직 수·동시 상담 수·저장량·SLO. NAS 총 메모리를 이 프로젝트의 가용 메모리로 가정하지 않는다. Organization별 사용량·한도 확장 가능성을 유지한다. |
| 기존 자산·호환성 | 기존 코드·데이터·서비스·클라이언트와 유지해야 할 관계 | 확정: SHNEA 연동은 실제 계약을 확인한다. 기존 OIDC·File·Editor·Job을 중복 개발하지 않고 구·신 버전 API/Event/DB 호환을 검토한다. |
