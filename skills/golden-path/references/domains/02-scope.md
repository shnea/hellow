# 기능·사용자 흐름·범위

필요시 확인: 기능 추가·수정, 업무 규칙·완료 조건 확인.

적용 범위: 공통 정의 항목. 다음 구현 단위를 정할 만큼 구체화한다.

| 항목 | 함께 정할 내용 | 상태·현재 기준·근거 |
| --- | --- | --- |
| 핵심 흐름 | 시작 조건 → 사용자 행동 또는 입력 → 기대 결과 | 확정: 플랫폼 관리형 조직 온보딩과 고객 웹 상담 → Queue → ACD → 수락 → WebRTC → 상담 기록·후속 업무를 우선한다. |
| 기능과 우선순위 | 반드시 필요한 것, 나중에 추가할 것, 기능 간 선후관계 | 확정: 원문 60장 MVP 우선. Phase 2~4는 아래 단계표에 보존한다. 예시와 후보를 즉시 구현 범위로 확대하지 않는다. |
| 포함·제외 범위 | 이번에 할 일과 의도적으로 하지 않을 일 | 확정: 첫 채널은 WebRTC. PSTN 발신, 외부 통합 채팅, Widget·SDK, AI 확장 전체를 MVP로 취급하지 않는다. |
| 도메인 규칙 | 상태 전환, 계산, 날짜·단위 등 틀리면 안 되는 업무 규칙 | 확정: 회원가입과 조직 가입, Interaction과 Consultation, 통화 종료와 후처리, 통화 이관과 업무 이관을 구분한다. |
| 오류·경계 상황 | 빈 입력, 취소, 중복, 잘못된 값, 실패 시 사용자 기대 | 확정: 미등록 고객도 상담 가능. 개별 상담사의 미수신과 요청 전체 실패를 구분하고 중복 콜백을 만들지 않는다. 보류와 음소거는 별도 동작이다. |
| 완료 조건 | 요구사항별 확인 가능한 동작과 결과 | 확정: 해당 단계의 정상·거부·실패·복구 경로를 검증한다. 구현·검증 상태는 요구사항 행별로 기록한다. |

새 프로젝트의 사용자 흐름과 기능을 여기서 구체화한다. 범용 항목을 그대로 기능 목록으로 옮기지 않는다.

| ID | 요구사항·사용자 흐름 | 입력·기대 결과·확인 방법 | 우선순위 | 현재 상태 |
| --- | --- | --- | --- | --- |
| MVP-01 | OIDC 로그인·Platform Super Admin·Organization 생성·최초 Admin·초대·로그인 이력·Team·Role·Permission·Data Scope | 가입 후 자동 조직/권한 없음, 조직 격리·권한 회수·관리자 보호·관측 가능한 로그인 이력 검증 | MVP | 부분 구현: Bearer JWT·API audience 검증, Organization/Membership/Permission/ORG 서버 격리와 권한 회수 테스트. 실제 OIDC 발급 계약·첫 조직 권한 배정, 관리자 UI·Team·SELF/TEAM 등은 남음 |

## 2026-10-03 추가 확정 기능과 순서

사용자가 아래 검토안을 승인했다. 기능 구현 완료 기록이 아니며 원문 단계표의 관련 항목을 구체화한다. 공통 기본값·조직 오버라이드는 분류·템플릿 등 아래 필수 설정부터 앞당겨 적용한다. 원문 Phase 2의 모든 설정 확장을 앞당기는 뜻은 아니다.

| 기능 | 확정 범위 | 현재 구현 상태 |
| --- | --- | --- |
| 관리자 화면 두 개 | 최고관리자는 공통 기본 설정·조직 생성·조직 관리자 지정과 대상 조직의 관리 기능을 수행한다. 조직관리자는 자기 조직 설정을 관리한다. 조직 관리 기능은 재사용하며 조직 맥락을 명시한다. | 일부 조직/Membership API만 존재. 화면·설정 관리 미구현 |
| 조직도·권한 | Organization → Team → Member, 계층형 Team 지원 가능 구조. 조직관리자가 Role/Permission/Data Scope를 조정하고 같은 조직 관리자를 추가한다. 복잡한 조직도 Builder는 초기 제외. | 계층 팀·직원 팀/역할 배치·동적 권한·SELF/TEAM/ORG·역할 기반 마지막 관리자 보호 구현, 서버/합성 화면 검수. 실제 조직 사용 검수는 남음 |
| 상담 분류 | 대·중·소 최대 3단계, 1~3단계 사용 가능. 공통 기준을 조직에서 상속·오버라이드한다. | 고정 대·중 2단계 목록 |
| 템플릿 | 공통 기본·조직 공유·개인 템플릿 구분. 조직관리자는 공유 템플릿, 개인은 자기 템플릿을 지정한다. | 화면 코드에 고정된 템플릿 |
| 상태 모니터링 | 조직관리자가 권한 범위 내 다른 직원의 상담 상태를 조회한다. 내용 열람·통화 청취는 별도 권한. | 서버 기반 관리 모니터링 미구현 |
| 지식관리 | 지식 목록·검색·원문 보기와 관리 기능 제공. AI는 허용된 지식을 검색해 출처·원문 링크와 함께 응답하며 AI 장애 시에도 직접 열람 가능. | 미구현·후반 작업 |
| 조직 내부 채팅 | 직원 간 조직 내부 채팅. 고객 상담 채팅·외부 채널 연동과 별도 범위. 방 유형·보존기간·알림 상세는 구현 전 결정. | 미구현·후반 작업 |

작업 순서: 실제 인증·첫 조직 권한 계약 확인 → 관리자 권한·공통/조직 설정 → 조직도·역할 → 3단계 분류·템플릿 → 상태 모니터링 → 지식관리·AI·조직 내부 채팅. AI와 채팅 구현은 후반에 하되 조직·팀·문서 접근 경계는 앞 단계에서 준비한다. 기존 파일 정책·통화·운영 데이터 수락 검증은 관련 단계에서 계속 수행한다.

상속과 과거 기록 보존은 [데이터 기준](06-data.md#공통-설정분류템플릿의-상속과-기록-보존), 관리자·지식·채팅 접근은 [보안 기준](07-security.md#관리자-및-추가-기능의-접근-경계)을 따른다.

## 리뷰 수정의 구현 경계와 남은 일

- 완료한 수정: 인증 거부 기본값, 조직별 서버 조회·권한 확인, PRIVATE 파일 소유 관계, 상담별 초안과 완료 트랜잭션, 실제 이력 재조회, 순차 폴링과 오류 표시. 상세 처리와 근거는 [리뷰 수정 결과](../../../../docs/review-repair.md)를 따른다.
- 설정·운영 수락 전: 실제 OIDC issuer/API audience와 첫 조직·직원 Membership, 승인된 파일 보존 정책, 기존 PUBLIC 파일 조사·이관, 운영 DB migration/restore, NAS 배포를 확인해야 한다.
- 제품 통합 수락 전: HTTPS 마이크 권한, 실제 2인 WebRTC 통화, LiveKit 참가자 제거 실패·재시작과 권한 회수 뒤 실제 연결 종료를 검증해야 한다. 관리자 UI·TEAM/SELF·등록 전 이력 연결은 코드/격리 검수가 있으며 실제 사용자 수락은 남아 있다. ACD 가용 상태·예약/이관·모니터링은 후속 구현이다.

MVP 전체는 완료되지 않았다. 이번 서버·화면 테스트 통과 범위와 미실행 검증은 [검증 영역](11-validation.md)에 기록한다.
